IDE સત્ર વિના Cursorને OmniRouteની પાછળ મૂકવાની બે રીતો:

1. **`cursor-api` પ્રોવાઇડર** (કાર્ડ "Cursor API", ઉપનામ `cua`): API કી-આધારિત
   પ્રોવાઇડર, જે Cursor વપરાશકર્તાની API કી (`crsr_…`, જે
   `https://cursor.com/dashboard/api` પર જનરેટ થાય છે) રાખે છે. ત્યારબાદ કોઈપણ OmniRoute ક્લાયન્ટ
   સામાન્ય ક્વોટા, ફૉલબૅક અને લૉગિંગ સ્તરો સાથે `/v1/chat/completions` દ્વારા
   `cursor-api/<model>` અથવા `cua/<model>` તરીકે Cursor મોડલ્સને ઍક્સેસ કરી શકે છે. IDE
   પ્રોવાઇડર (`cursor`, OAuth/IDE સત્ર) યથાવત્ રહે છે.
2. **Cursor CLI પાસથ્રૂ**: Cursor CLI (`agent`)ને OmniRoute તરફ નિર્દેશિત કરો, જેથી
   CLI દ્વારા કરવામાં આવતી દરેક RPC OmniRoute API કી વડે પ્રમાણિત થાય, તેને
   `cursor-api` કનેક્શનના ક્રેડેન્શિયલ સાથે Cursorને ફૉર્વર્ડ કરવામાં આવે અને
   Logs પેજમાં નોંધવામાં આવે.

## કીનું એક્સચેન્જ શા માટે થાય છે

`api2.cursor.sh` કાચી `crsr_…` કીને Bearer ટોકન તરીકે નકારે છે (401). Cursor
CLI પહેલાં કીને `/auth/exchange_user_api_key` પર POST કરે છે અને એક કલાક પછી
સમાપ્ત થતું સત્ર JWT મેળવે છે; પરત મળતું `refreshToken` પણ એ જ
`exp` ધરાવે છે, તેથી રિફ્રેશ કરવાનો અર્થ કીનું ફરી એક્સચેન્જ કરવું છે.
`open-sse/services/cursorApiKeyAuth.ts` એ એક્સચેન્જ કરે છે, દરેક કી દીઠ એક સત્ર
ટોકન કૅશ કરે છે, સમાપ્તિના પાંચ મિનિટ પહેલાં ફરી એક્સચેન્જ કરે છે અને Cursor
401 સાથે જવાબ આપે ત્યારે કૅશ કરેલું ટોકન દૂર કરે છે. `CursorExecutor`
`cursor-api` કનેક્શન્સ માટે અપસ્ટ્રીમ સ્ટ્રીમ ખોલતાં બરાબર પહેલાં તેને કૉલ કરે છે.

## `cursor-api` પ્રોવાઇડર

રજિસ્ટ્રી: `open-sse/config/providers/registry/cursor/index.ts`
(`cursor_apiProvider`, `authType: "apikey"`, `cursor` જેવા જ `format`, `baseUrl` અને
`models`). કૅટલૉગ કાર્ડ:
`src/shared/constants/providers/apikey/specialty-media.ts`. એક્ઝિક્યુટર મૅપ:
`open-sse/executors/index.ts` (`"cursor-api"` / `cua` →
`new CursorExecutor("cursor-api")`).

ડૅશબોર્ડ: Providers → Cursor API → Add API key.

REST:

```bash
curl -sS -X POST http://localhost:20128/api/providers \
  -H "Content-Type: application/json" \
  -d '{"provider":"cursor-api","name":"cursor-api-key","apiKey":"crsr_…","priority":1}'
```

ત્યારબાદ:

```bash
curl -sS http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <omniroute-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"cursor-api/auto","messages":[{"role":"user","content":"say PONG"}]}'
```

નોંધો:

- `cursor-api` માટેની મોડલ સૂચિ સ્ટૅટિક Cursor રજિસ્ટ્રીમાંથી આવે છે (એ જ
  સૂચિનો IDE પ્રોવાઇડર ફૉલબૅક તરીકે ઉપયોગ કરે છે); OmniRoute હોસ્ટ પર
  `cursor-agent` ઇન્સ્ટૉલ કરવાની જરૂર નથી.
- `POST /api/providers/{id}/refresh-cursor` ફક્ત `cursor` IDE પ્રોવાઇડર માટે
  છે; `cursor-api` કનેક્શન્સ પાસે રિન્યૂ કરવા માટે કોઈ IDE સત્ર હોતું નથી.

## Cursor CLI પાસથ્રૂ

રૂટ: `src/app/api/cursor-cli/[...path]/route.ts` →
`open-sse/handlers/cursorCliProxy.ts`. `/api/cursor-cli/` પ્રીફિક્સ
`src/shared/constants/publicApiRoutes.ts`માં રજિસ્ટર થયેલો છે, કારણ કે હૅન્ડલર
પોતાનું પ્રમાણીકરણ લાગુ કરે છે:

| પાથ                                                                                                                       | CLI પાસેથી અપેક્ષિત પ્રમાણીકરણ | OmniRoute શું કરે છે                                                                                                                                               |
| ------------------------------------------------------------------------------------------------------------------------- | ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `POST /auth/exchange_user_api_key`                                                                                        | `Bearer <OmniRoute API key>`   | કીને માન્ય કરે છે, 1 કલાકનું HS256 JWT (`JWT_SECRET` વડે સાઇન કરેલું) બનાવે છે અને તેને પરત કરે છે                                                                 |
| દરેક અન્ય પાથ (`/aiserver.v1.*`, `/agent.v1.AgentService/RunSSE`, `/aiserver.v1.BidiService/BidiAppend`, `/v1/traces`, …) | `Bearer <that JWT>`            | ઇશ્યૂઅર/ઑડિયન્સ/સમાપ્તિ ચકાસે છે, સક્રિય `cursor-api` કનેક્શન પસંદ કરે છે, Authorization હેડરને એક્સચેન્જ કરેલા Cursor ટોકનથી બદલે છે અને જવાબ પાછો સ્ટ્રીમ કરે છે |

CLI તેને મળતા કોઈપણ ટોકનમાંથી `exp` ડિકોડ કરે છે, તેથી તેને અપારદર્શક
ટોકન આપવાથી તે લગભગ દરેક વિનંતી પહેલાં ફરી એક્સચેન્જ કરે છે; બનાવેલું JWT
આવું થતું અટકાવે છે. OmniRoute તરફથી મળતો 401 CLIને ફરી એક્સચેન્જ કરવા પ્રેરે છે.

### સેટઅપ

1. OmniRoute API કી (Dashboard → API keys) અને `cursor-api`
   કનેક્શન બનાવો.
2. CLIને agent સ્ટ્રીમ માટે HTTP/1.1 વાપરવા કહો.
   `~/.cursor/cli-config.json`માં:

   ```json
   { "network": { "useHttp1ForAgent": true } }
   ```

   આ વિના CLI અલગથી કન્ફિગર કરેલા agent હોસ્ટ પર HTTP/2 દ્વારા agent ટર્ન
   ખોલે છે અને ફક્ત કન્ટ્રોલ-પ્લેન RPCs જ એન્ડપોઇન્ટમાંથી પસાર થાય છે.

3. OmniRoute સામે CLI ચલાવો:

   ```bash
   export CURSOR_API_ENDPOINT=http://localhost:20128/api/cursor-cli
   export CURSOR_API_KEY=<omniroute-api-key>
   agent -p --trust "Reply with exactly OK"
   ```

દરેક હૉપ Logsમાં પ્રોવાઇડર `cursor-api`, વિનંતી પ્રકાર `cursor-cli` અને
પાથ `/api/cursor-cli/<rpc>` તરીકે નોંધાય છે તથા તેને OmniRoute API કી અને
તેને સેવા આપનાર કનેક્શન સાથે સાંકળવામાં આવે છે.

### નિષ્ફળતાની પરિસ્થિતિઓ

| પરિસ્થિતિ                                      | CLI માટેનો પ્રતિભાવ                                       |
| ---------------------------------------------- | --------------------------------------------------------- |
| અજ્ઞાત OmniRoute કી અને `REQUIRE_API_KEY=true` | એક્સચેન્જ પર 401 `unauthenticated`                        |
| `REQUIRE_API_KEY=false`                        | અનામી સત્ર (`/v1/*` ની વર્તણૂકને પ્રતિબિંબિત કરે છે)      |
| સમયસમાપ્ત / વિદેશી / ચેડાં કરાયેલ સત્ર JWT     | 401, CLI ફરીથી એક્સચેન્જ કરે છે                           |
| એક્સચેન્જ પછી OmniRoute API કી રદ કરવામાં આવી  | આગામી RPC પર 401                                          |
| કોઈ સક્રિય `cursor-api` કનેક્શન નથી            | 503 `unavailable`                                         |
| Cursor કનેક્શનની કી નકારે છે                   | 401 `unauthenticated`, કૅશ કરાયેલ સત્ર દૂર કરવામાં આવે છે |
| અપસ્ટ્રીમ સુધી પહોંચી શકાતું નથી               | 502 `unavailable` (શુદ્ધ કરાયેલ સંદેશ)                    |
| `JWT_SECRET` સેટ નથી                           | એક્સચેન્જ પર 503                                          |
