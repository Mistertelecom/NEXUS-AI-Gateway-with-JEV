Kaks võimalust Cursori paigutamiseks OmniRoute'i taha ilma IDE-seansita:

1. **`cursor-api` pakkuja** (kaart „Cursor API“, alias `cua`): API-võtme
   pakkuja, mis hoiab Cursori kasutaja API-võtit (`crsr_…`, loodud aadressil
   `https://cursor.com/dashboard/api`). Seejärel pääseb iga OmniRoute'i klient
   Cursori mudelitele ligi `/v1/chat/completions` kaudu mudelina
   `cursor-api/<model>` või `cua/<model>`, kasutades tavapäraseid kvoodi-,
   varuvariandi- ja logimiskihte. IDE-pakkuja (`cursor`, OAuth/IDE-seanss) jääb
   muutmata.
2. **Cursor CLI läbipääs**: suuna Cursor CLI (`agent`) OmniRoute'i, et
   iga CLI tehtud RPC autentitaks OmniRoute'i API-võtmega, edastataks
   Cursorile `cursor-api` ühenduse mandaadiga ning salvestataks lehel
   Logid.

## Miks võti vahetatakse

`api2.cursor.sh` lükkab töötlemata `crsr_…` võtme Bearer-loana tagasi (401). Cursor
CLI saadab võtme esmalt POST-päringuga lõpp-punkti `/auth/exchange_user_api_key` ja saab
vastuseks seansi JWT, mis aegub ühe tunni pärast; tagastatud `refreshToken` sisaldab sama
`exp` väärtust, seega tähendab värskendamine võtme uuesti vahetamist.
`open-sse/services/cursorApiKeyAuth.ts` teeb selle vahetuse, salvestab vahemällu ühe seansi
loa võtme kohta, vahetab selle uuesti viis minutit enne aegumist ja eemaldab vahemällu
salvestatud loa, kui Cursor vastab koodiga 401. `CursorExecutor` kutsub seda vahetult enne
ülesvoolu voo avamist `cursor-api` ühenduste jaoks.

## `cursor-api` pakkuja

Register: `open-sse/config/providers/registry/cursor/index.ts`
(`cursor_apiProvider`, `authType: "apikey"`, sama `format`, `baseUrl` ja
`models` nagu `cursor`). Kataloogikaart:
`src/shared/constants/providers/apikey/specialty-media.ts`. Täiturite vastendus:
`open-sse/executors/index.ts` (`"cursor-api"` / `cua` →
`new CursorExecutor("cursor-api")`).

Juhtpaneel: Pakkujad → Cursor API → Lisa API-võti.

REST:

```bash
curl -sS -X POST http://localhost:20128/api/providers \
  -H "Content-Type: application/json" \
  -d '{"provider":"cursor-api","name":"cursor-api-key","apiKey":"crsr_…","priority":1}'
```

Seejärel:

```bash
curl -sS http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <omniroute-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"cursor-api/auto","messages":[{"role":"user","content":"say PONG"}]}'
```

Märkused:

- `cursor-api` mudelite loend pärineb staatilisest Cursori registrist (samast
  loendist, mida IDE-pakkuja kasutab varuvariandina); `cursor-agent` paigaldamine
  OmniRoute'i hosti pole vajalik.
- `POST /api/providers/{id}/refresh-cursor` on mõeldud ainult `cursor` IDE-pakkujale;
  `cursor-api` ühendustel pole uuendamist vajavat IDE-seanssi.

## Cursor CLI läbipääs

Marsruut: `src/app/api/cursor-cli/[...path]/route.ts` →
`open-sse/handlers/cursorCliProxy.ts`. Prefiks `/api/cursor-cli/` on
registreeritud failis `src/shared/constants/publicApiRoutes.ts`, sest töötleja
jõustab oma autentimise:

| Tee                                                                                                                        | CLI-lt oodatav autentimine   | Mida OmniRoute teeb                                                                                                                                                |
| -------------------------------------------------------------------------------------------------------------------------- | ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `POST /auth/exchange_user_api_key`                                                                                         | `Bearer <OmniRoute API key>` | Valideerib võtme, loob 1-tunnise HS256 JWT (allkirjastatud võtmega `JWT_SECRET`) ja tagastab selle                                                                 |
| kõik muud teed (`/aiserver.v1.*`, `/agent.v1.AgentService/RunSSE`, `/aiserver.v1.BidiService/BidiAppend`, `/v1/traces`, …) | `Bearer <that JWT>`          | Kontrollib väljaandjat/sihtrühma/aegumist, valib aktiivse `cursor-api` ühenduse, asendab Authorization-päise vahetatud Cursori loaga ja voogedastab vastuse tagasi |

CLI dekodeerib `exp` väärtuse igast saadud loast, seega põhjustab läbipaistmatu
loa andmine selle uuesti vahetamise peaaegu enne iga päringut; loodud JWT väldib
seda. OmniRoute'i vastus 401 paneb CLI loa uuesti vahetama.

### Seadistamine

1. Loo OmniRoute'i API-võti (Juhtpaneel → API-võtmed) ja `cursor-api`
   ühendus.
2. Määra CLI kasutama agendivoo jaoks HTTP/1.1. Failis
   `~/.cursor/cli-config.json`:

   ```json
   { "network": { "useHttp1ForAgent": true } }
   ```

   Ilma selleta avab CLI agendi suhtluse HTTP/2 kaudu eraldi
   seadistatud agendihostiga ja lõpp-punkti kaudu liiguvad ainult
   juhtimistasandi RPC-d.

3. Käivita CLI OmniRoute'i suhtes:

   ```bash
   export CURSOR_API_ENDPOINT=http://localhost:20128/api/cursor-cli
   export CURSOR_API_KEY=<omniroute-api-key>
   agent -p --trust "Reply with exactly OK"
   ```

Iga etapp jõuab logidesse pakkujana `cursor-api`, päringu tüübina `cursor-cli`,
teega `/api/cursor-cli/<rpc>` ning seostatakse OmniRoute'i API-võtme ja päringut
teenindanud ühendusega.

### Tõrkerežiimid

| Olukord                                             | Vastus CLI-le                                          |
| --------------------------------------------------- | ------------------------------------------------------ |
| Tundmatu OmniRoute'i võti ja `REQUIRE_API_KEY=true` | 401 `unauthenticated` vahetamisel                      |
| `REQUIRE_API_KEY=false`                             | anonüümne seanss (vastab `/v1/*` käitumisele)          |
| Aegunud / võõras / muudetud seansi JWT              | 401, CLI vahetab selle uuesti                          |
| OmniRoute'i API-võti tühistati pärast vahetamist    | 401 järgmisel RPC-l                                    |
| Aktiivne `cursor-api` ühendus puudub                | 503 `unavailable`                                      |
| Cursor lükkab ühenduse võtme tagasi                 | 401 `unauthenticated`, puhverdatud seanss eemaldatakse |
| Ülemteenus pole kättesaadav                         | 502 `unavailable` (puhastatud sõnum)                   |
| `JWT_SECRET` pole määratud                          | 503 vahetamisel                                        |
