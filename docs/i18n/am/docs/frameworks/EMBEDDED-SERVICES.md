## 1. አጠቃላይ እይታ

### የተካተቱ አገልግሎቶች ለምን ያስፈልጋሉ?

አምስት አገልግሎቶች ተካተዋል፦

| አገልግሎት          | npm ጥቅል                            | ነባሪ ወደብ | ዓላማ                                                                                                                                           |
| --------------- | ---------------------------------- | :-----: | --------------------------------------------------------------------------------------------------------------------------------------------- |
| **9Router**     | `9router`                          |  20130  | OmniRoute እንደ ንዑስ አቅራቢ ሊጠቀምበት የሚችል AI ራውተር። ሞዴሎች እንደ `9router/{sub}/{model}` ይቀርባሉ                                                            |
| **CLIProxyAPI** | የGitHub ልቀት ባይነሪ (`cliproxy`)      |  8317   | ለAnthropic CLI የማረጋገጫ ፍሰቶች የአካባቢ ፕሮክሲ አስማሚ። የOAuth ቶከኖች ጊዜያቸው ሲያልቅ ተተኪ ማዘዋወርን ያቀርባል                                                           |
| **Mux**         | `mux` (ያለ ግራፊክ በይነገጽ `mux server`) |  8322   | የአካባቢ ወኪል-ማቀናበሪያ ዴሞን (coder/mux)። የሕይወት ዑደቱ ብቻ የሚተዳደር — የማዘዋወሪያ ዒላማ አይደለም (የLLM ፕሮክሲ ማድረግ የለም)።                                               |
| **Bifrost**     | `@maximhq/bifrost`                 |  8080   | የGo AI-ጌትዌይ ማስተላለፊያ የኋላ-ጫፍ። በሚሰራበት ጊዜ በማስተላለፊያ መስመሩ (`/v1/relay/`) በራስ-ሰር ይመረጣል                                                               |
| **Dario**       | `@askalf/dario`                    |  3456   | የClaude ምዝገባ ፕሮክሲ — ለClaude-Code ቅርጽ ላለው ትራፊክ የCLIProxyAPI አማራጭ/ተተኪ፤ የገባው ቁልፍ `DARIO_ADMIN_TOKEN` በመሆን የእሱን `/admin/*` OAuth መቆጣጠሪያ ክፍል ይጠብቃል |

አምስቱም ተመሳሳይ የቁጥጥር ሞዴል ይከተላሉ፦

- OmniRoute በ`DATA_DIR/services/{name}/` ስር ይጭናቸዋል (ከOmniRoute የራሱ `package.json` ተለይተው)
- OmniRoute እንደ ልጅ ሂደቶች ያስጀምራቸዋል እና ይከታተላቸዋል
- OmniRoute ጊዜያዊ API ቁልፍን ወደ ልጅ ሂደቱ አካባቢ ያስገባል፣ እንዲሁም አገልግሎቱን ሳያቋርጥ ያድሰዋል (ተግባራዊ በሚሆንበት ቦታ)
- ሁሉም የአስተዳደር መስመሮች (`/api/services/*`) **LOCAL_ONLY** ናቸው — ከloopback ብቻ ተደራሽ ናቸው (ጥብቅ ደንብ #17)

### ቁልፍ ውሳኔዎች (ከንድፍ ዕቅዱ)

| ውሳኔ                           | እሴት                                                               |
| ----------------------------- | ----------------------------------------------------------------- |
| የዳሽቦርድ መዳረሻ ወደ 9Router ቤተኛ UI | በ`/dashboard/providers/services/9router/embed/*` ላይ Reverse proxy |
| የመጫኛ ዘዴ                       | `npm install {package}` በ`execFile` በኩል (የshell እሴት ማስገባት የለም)    |
| የአጠቃቀም ሁነታ                    | አቅራቢው በማዘዋወሪያ ሞተሩ ውስጥ እንደ `9router/{sub}/{model}` ይመዘገባል          |
| የAPI ቁልፍ አስተዳደር               | OmniRoute ያመነጫል፣ በማከማቻ ላይ ያመሰጥራል (AES-256-GCM)፣ እና በenv በኩል ያስገባል |
| የዳሽቦርድ አካባቢ                   | `/dashboard/providers/services` (ሦስት ትሮች)                         |
| ራስ-ሰር ማስጀመር                   | ለእያንዳንዱ አገልግሎት የማብሪያ/ማጥፊያ አማራጭ፣ ነባሪው OFF                          |

## 3. የሕይወት ዑደት ሁኔታ ማሽን

```
                    install()
  ┌─────────────┐ ──────────► ┌─────────────┐
  │ not_installed│             │   stopped   │◄──────────────────┐
  └─────────────┘             └──────┬──────┘                   │
                                     │ start()                   │
                                     ▼                           │ stop()
                               ┌──────────┐                      │
                               │ starting │                      │
                               └────┬─────┘                     │
              የጤና ምርመራው ተሳክቷል │         ብልሽት / SIGTERM    │
                               ┌────▼─────┐  (በ5s ውስጥ ይወጣል) │
                               │ running  │──── ብልሽት ─────────►┤
                               └────┬─────┘                   ┌─▼────┐
                             stop() │                          │error │
                                    ▼                          └──────┘
                               ┌──────────┐
                               │ stopping │
                               └──────────┘
```

ሁኔታዎች በ`version_manager` DB ሰንጠረዥ (`status` ዓምድ) ውስጥ ይቀመጣሉ፣ እንዲሁም
በ`ServiceSupervisor` የማህደረ ትውስታ ውስጥ ሁኔታ ይንጸባረቃሉ። እየሰራ ላለ ሂደት የማህደረ ትውስታው
ሁኔታ ወሳኝ ምንጭ ነው፤ የDB ሁኔታው ደግሞ ሲነሳ ዘላቂ መጠባበቂያ ነው።

### የሁኔታ ሽግግሮች

| ከ               | ክስተት                          | ወደ                     |
| --------------- | ----------------------------- | ---------------------- |
| `not_installed` | `install()` ተሳክቷል             | `stopped`              |
| `stopped`       | `start()` ተጠርቷል               | `starting`             |
| `starting`      | የጤና ምርመራው 200 መለሰ             | `running`              |
| `starting`      | ሂደቱ ጤናማ ከመሆኑ በፊት ወጣ           | `error`                |
| `running`       | `stop()` ተጠርቷል                | `stopping` → `stopped` |
| `running`       | ሂደቱ ሳይጠበቅ ወጣ (< 5 s)          | `error` (ፈጣን ብልሽት)     |
| `running`       | ሂደቱ ሳይጠበቅ ወጣ (> 5 s)          | `error`                |
| `error`         | `start()` ተጠርቷል               | `starting`             |
| ማንኛውም           | `stopping` በሚሆንበት ጊዜ `stop()` | ምንም አያደርግም             |

### የክወና መቆለፊያ

`ServiceSupervisor` የሕይወት ዑደት ክወናዎችን በasync የክወና መቆለፊያ
(`withLock()`) ተከታታይ ያደርጋል። በአንድ supervisor ላይ በአንድ ጊዜ የሚደረጉ `start()` ጥሪዎች
በትክክል አንድ spawn ብቻ ያስከትላሉ፤ ሁለተኛው ጠሪ ይጠብቃል እና ያለውን ሁኔታ ይመልሳል።
ይህ፣ ለምሳሌ auto-start እና የUI አዝራር በአንድ ጊዜ ሲነሱ፣ የውድድር ሁኔታዎችን
ይከላከላል።

## 4. የAPI ማጣቀሻ

በ`/api/services/` ስር ያሉ ሁሉም routes **LOCAL_ONLY** ናቸው (loopback ብቻ፣ ጥብቅ ደንብ #17)።
ከloopback ውጭ የሆኑ ጥያቄዎች auth token ቢኖራቸውም `403 LOCAL_ONLY` ይቀበላሉ።

### 4.1 የ9Router endpoints (11 routes)

#### `POST /api/services/9router/install`

9Routerን ከnpm ይጫናል። የራሱ `package.json` እና `node_modules/` ያሉትን
`DATA_DIR/services/9router/` ይፈጥራል። ከOmniRoute የራሱ deps ጋር አይጋጭም።

**የጥያቄ አካል** (ሁሉም አማራጭ ናቸው):

```json
{ "version": "latest" }
```

| መስክ       | ዓይነት     | ነባሪ        | መግለጫ                             |
| --------- | -------- | ---------- | -------------------------------- |
| `version` | `string` | `"latest"` | የሚጫነው npm version tag ወይም semver |

**ምላሾች:**

| ሁኔታ   | መግለጫ                                                       |
| ----- | ---------------------------------------------------------- |
| `200` | `{ ok: true, installedVersion: "x.y.z", path: "..." }`     |
| `400` | ልክ ያልሆነ የጥያቄ አካል (የZod ማረጋገጫ አልተሳካም)                       |
| `409` | አስቀድሞ በመጫን ላይ ነው (መቆለፊያው ተይዟል)                             |
| `500` | npm install አልተሳካም — ቀላል የስህተት መልዕክት ለማየት `message`ን ይመልከቱ |

**ማስታወሻዎች:** `execFile('npm', [...])`ን ይጠቀማል — shell የለም፣ interpolation የለም (ጥብቅ ደንብ #13)።
የEACCES ስህተቶች በቀላሉ ሊገቡ እንደሚችሉ መልዕክቶች ይቀርባሉ።

```json
}
```

### 4.6 ተቃራኒ ፕሮክሲ (የ9Router ዳሽቦርድ መክተቻ)

ዳሽቦርዱ የ9Router ድር UIን በውስጣዊ ተቃራኒ
ፕሮክሲ በኩል በiframe ውስጥ ያካትታል፦

```
GET|POST|... /dashboard/providers/services/9router/embed/[...path]
```

ይህ ፕሮክሲ፦

- ጥያቄውን ወደ `http://127.0.0.1:{port}/{path}` ያስተላልፋል (loopback ብቻ)
- ገቢ `cookie` እና `authorization` ራስጌዎችን ያስወግዳል (የOmniRoute ክፍለ ጊዜ መረጃ እንዳይፈስ)
- ለ9Router ማረጋገጫ `Authorization: Bearer {apiKey}`ን ያስገባል
- ከምላሹ `set-cookie`፣ `content-security-policy`፣ `x-frame-options`፣ `cross-origin-*`ን ያስወግዳል
- `<base href>`ን ለማስገባት እና ፍጹም መንገዶችን መደበኛ ለማድረግ (`/foo` → `/dashboard/.../embed/foo`) የHTML ምላሾችን እንደገና ይጽፋል

ለተካተተው ዳሽቦርድ የWebSocket ማሻሻያዎች በተለየ
ፖርት ላይ ባለ አጋር አገልጋይ ይስተናገዳሉ (`src/lib/services/embedWsProxy.ts`ን ይመልከቱ)።

**ደህንነት:** የመክተቻ ፕሮክሲ መስመሮች በ`LOCAL_ONLY_API_PREFIXES` ስር የተመደቡ ሲሆን
ከloopback ብቻ ሊደረስባቸው ይችላል። በCloudflare/Ngrok ቱነል በኩል JWT ያገኘ አጥቂ
ወደ ተካተቱ አገልግሎቶች በፕሮክሲ መግባት አይችልም።

## 5. ደህንነት

### LOCAL_ONLY ማስገደጃ (ጥብቅ ደንብ #17)

በ `/api/services/` እና `/dashboard/providers/services/*/embed/` ስር ያሉ ሁሉም መስመሮች
በ `src/server/authz/routeGuard.ts` ውስጥ LOCAL_ONLY ተብለው ተመድበዋል። የloopback ማረጋገጫው
ከማንኛውም የማረጋገጫ ቅርንጫፍ በፊት ያለምንም ሁኔታ ይሠራል፦

```
ጥያቄው ይደርሳል
  → isLocalOnlyPath(path)?
      → loopback ያልሆነ → 403 LOCAL_ONLY (ሁልጊዜ፣ ከማረጋገጫው በፊት)
      → loopback የሆነ    → ወደ መደበኛው ማረጋገጫ ይቀጥላል
```

ይህ የወጣ JWT (ለምሳሌ፣ በtunnel በኩል) `npm install` እንዳያስጀምር ወይም
process እንዳይፈጥር ይከላከላል። ሙሉውን የደረጃ ማትሪክስ ለማየት
`docs/security/ROUTE_GUARD_TIERS.md`ን ይመልከቱ።

### የAPI ቁልፍ ማስገባት

9Router እና Mux ለራሳቸው HTTP endpoints የAPI ቁልፍ/bearer token ያስፈልጋቸዋል።
OmniRoute፦

1. ለአገልግሎቱ የተለየ ቅድመ ቅጥያ (`nr_` ለ9Router፣ `mx_` ለMux) በመጠቀም
   በ `crypto.randomBytes(32).toString("base64url")` ቁልፍ ያመነጫል።
2. AES-256-GCMን በመጠቀም በማከማቻ ላይ ያመሰጥረዋል (ለprovider ማረጋገጫ መረጃዎች
   የሚያገለግለው ተመሳሳይ cipher)።
3. በprocess መፍጠሪያ ጊዜ ዲክሪፕት አድርጎ እንደ environment variable ያስገባዋል —
   `NINEROUTER_API_KEY` ለ9Router፣ `MUX_SERVER_AUTH_TOKEN` ለMux (በፍጹም እንደ CLI
   flag አይተላለፍም፣ ስለዚህ tokenው በ `ps`/process ዝርዝሮች ውስጥ አይታይም)።
4. ግልጽ ያልተመሰጠረውን ቁልፍ በማንኛውም HTTP ምላሽ ውስጥ አይመልስም።

CLIProxyAPI በprocess መፍጠሪያ ጊዜ የሚገባ የተወሰነ data-plane ቁልፍ ይቀበላል
(`needsApiKey: true` — ከadapter ጋር ለmodel sync ያገለግላል)።

### የSSRF መከላከያ

የreverse HTTP proxy (`/dashboard/.../embed/[...path]`) ጥያቄዎችን ወደ
`http://127.0.0.1:{port}` ብቻ እንዲያስተላልፍ በቋሚነት ተዋቅሯል። ወደ loopback ያልሆኑ
መዳረሻዎች redirectsን ፈጽሞ አይከተልም። ከloopback ክልል ውጭ ወዳለ አድራሻ
የሚፈታ ማንኛውንም upstream URL ለመከልከል `ssrf-req-filter` library ጥቅም ላይ ይውላል።

### የShell ደህንነት (ጥብቅ ደንብ #13)

`npm install` የሚጠራው በ `execFile('npm', ['install', pkg, '--prefix', dir])` ነው —
template literals አይጠቀምም፣ shell አይጠቀምም፣ እንዲሁም ውጫዊ ዱካዎችን ወደ command
string አያስገባም። Runtime እሴቶች (ports፣ API ቁልፎች) በchild processው `env` object
በኩል ይተላለፋሉ።

### የስህተት ማጽዳት (ጥብቅ ደንብ #12)

ከ `/api/services/*` የሚመጡ ሁሉም የስህተት ምላሾች በ `buildErrorBody()` ወይም
`sanitizeErrorMessage()` በኩል ያልፋሉ። ጥሬ `err.stack` እና `err.message` ለጠሪው
በቀጥታ ፈጽሞ አይመለሱም።

#### ሊሰካ የሚችል provider-plugin ውል (Phase 1፣ #7333)

`src/lib/services/providerPlugins/` የአንድ backend `bootstrap.ts` `ServiceEntry` fieldsን እና
`serviceBackends.ts` manifest-template fieldsን ወደ አንድ object የሚያጠቃልል
`ServiceProviderPlugin` ውል ያስተዋውቃል፤ ይህም የአንድ backend ቅርጽ በሁለት ያልተያያዙ
ፋይሎች ውስጥ በተናጠል እንዳይገለጽ ያደርጋል። ይህ በተጻፈበት ጊዜ **`9router` ብቻ
ተዛውሯል** — `bootstrap.ts` የ `SERVICES[]` entryውን ከ
`getServiceProviderPlugin("9router")` (`src/lib/services/providerPlugins/registry.ts`)
ያመነጫል፤ pluginው በማንኛውም ጊዜ ከጠፋ የመነሻ ስህተት ይፈጥራል። `cliproxy`፣ `mux`፣ እና `bifrost`
ነባሮቹ የinline `SERVICES[]` literals ሳይቀየሩ እንዳሉ ይቆያሉ።

`open-sse/config/providerPluginManifest.ts` እንዲሁም በሚገባ የተቀረጸ
`ProviderPluginManifestEntry`ን ከ `SERVICE_BACKEND_MANIFEST_TEMPLATE` entry የሚገነባ
ተጨማሪ `createServiceBackendManifestEntry(pluginId, template)` helper አግኝቷል — እስካሁን
ድረስ ከማንኛውም በቀጥታ ከሚሠራ request path ጋር **አልተገናኘም** (`generateProviderPluginManifestFromRegistry()`
ወይም `/v1/providers/[provider]/models`)፤ ውሉ ለሁለተኛ backend ከተረጋገጠ በኋላ ይህ
በቀጣይ የሚሠራ ሥራ ነው።

በissue #7333 ስር ተከታትለው ወደ ቀጣይ PRs የተላለፉ ሥራዎች፦ `cliproxyapi`ን በተመሳሳይ
registry ማዛወር፣ `mux`/`bifrost`ን ወደ `ServiceBackendPluginId` union ማጠቃለል፣

`createServiceBackendManifestEntry()`ን በቀጥታ ከሚሠራ manifest/models code path ጋር ማገናኘት።

tunnel፣ MITM ሞጁሎች) ማስገባትን ያካትታል። ነባሪው የጤና ምርመራ ክፍተት 2 ሰከንድ ሲሆን፣
ተቆጣጣሪው ጊዜው እንዳለፈ ከማወጁ በፊት 3 ጊዜ ይሞክራል (ነገር ግን ሁኔታውን መጠየቁን ይቀጥላል)።

**መፍትሔ፦** `healthIntervalMs` እና የ`waitForHealthy` የጊዜ ገደብ
(`healthIntervalMs * 3`) በ`bootstrap.ts` ውስጥ ሊዋቀሩ ይችላሉ። ለመጀመር ረዘም ያለ
ጊዜ ለሚያስፈልጋቸው አገልግሎቶች፣ `healthIntervalMs`ን ወደ 5000 እና `stopTimeoutMs`ን ወደ 30 000 ያሳድጉ።

### የፖርት ግጭት (`EADDRINUSE`)

**ምልክቶች፦** ሎጎቹ `address already in use :::20130`ን ያሳያሉ።

**ምክንያቶች፦**

- ሌላ ሂደት ፖርት 20130ን አስቀድሞ እየተጠቀመ ነው።
- የቀድሞው የ9Router ሂደት ሙሉ በሙሉ አልቆመም (ዞምቢ PID)።

**መፍትሔ፦**

1. በ`.env` ውስጥ ባለው `NINEROUTER_PORT` የአካባቢ ተለዋዋጭ አማካኝነት ነባሪውን ፖርት ይቀይሩ።
2. ግጭቱን የሚፈጥረውን ሂደት ፈልገው ያቁሙ፦ `lsof -ti :20130 | xargs kill -9`።
3. ፖርቱ በ`bootstrap.ts` ውስጥ ባለው `port` መስክ አማካኝነት ለእያንዳንዱ አገልግሎት ሊዋቀር ይችላል።

**ማስታወሻ፦** 9Router ከOmniRoute ነባሪ ፖርት 20128 ጋር እንዳይጋጭ
በተለይ ፖርት 20130ን እንደ ነባሪ ይጠቀማል።

---

### በሚጫንበት ጊዜ ፈቃድ ተከልክሏል (EACCES)

**ምልክቶች፦** ጭነቱ 500 ይመልሳል፣ ሎጎቹም `EACCES` ወይም `permission denied`ን ያሳያሉ።

**ምክንያቶች፦**

- `DATA_DIR` ወይም ወላጅ ማውጫው በOmniRoute ሂደት ሊጻፍበት አይችልም።
- ከተያያዘው ቮልዩም ላይ የመጻፍ ፍቃድ ሳይኖር Dockerን rootless በሆነ ሁኔታ ማስኬድ።

**መፍትሔ፦**

1. `DATA_DIR`ን (ነባሪ፦ `~/.omniroute/`) ይፈትሹ፦ `ls -la ~/.omniroute/`
2. የOmniRoute ሂደቱ ተጠቃሚ የማውጫው ባለቤት መሆኑን ያረጋግጡ፦ `chown -R $USER ~/.omniroute/`
3. በDocker ውስጥ፣ የቮልዩም ማያያዣው ለኮንቴይነሩ ተጠቃሚ ትክክለኛ ፍቃዶች እንዳሉት ያረጋግጡ።

---

### ማዘመን አልተሳካም (`npm install` የጊዜ ገደብ ማለፍ ወይም የአውታረ መረብ ስህተት)

**ምልክቶች፦** ማዘመኑ `InstallError`ን የያዘ 500 ይመልሳል፣ ሎጎቹም የአውታረ መረብ የጊዜ ገደብ ማለፍን ያሳያሉ።

**የማረጋገጫ ዝርዝር፦**

1. npm registry ተደራሽ መሆኑን ያረጋግጡ፦ `npm ping`።
2. የድርጅት proxy መኖሩን ይፈትሹ፦ `npm config get proxy`፣ `npm config get https-proxy`።
3. ጭነቱን በእጅ ይሞክሩ፦ `npm install {package}@latest --prefix ~/.omniroute/services/{name}/`።
4. ከአውታረ መረብ በተገለለ አካባቢ ከሆኑ፣ tarballን አስቀድመው ያውርዱና `npm install /path/to/tarball.tgz`ን ይጠቀሙ።

### አገልግሎቱ ከተጀመረ በኋላ ወዲያውኑ `"error"` ሁኔታን ያሳያል (ፈጣን ብልሽት)

**ምልክቶች፦** ሁኔታው ከ5 ሰከንድ ባነሰ ጊዜ ውስጥ ከ`"starting"` ወደ `"error"` ይቀየራል።
`lastError` `"Fast crash (exited with code 1)"`ን ያሳያል።

**የማረጋገጫ ዝርዝር፦**

1. የሎጉን ሙሉ የመጨረሻ ክፍል ያንብቡ፦ `GET /api/services/{name}/logs?tail=500`።
2. የተለመደ ምክንያት፦ አገልግሎቱ የሚጠብቃቸው የአካባቢ ተለዋዋጮች አለመኖር።
3. ለ9Router፦ `NINEROUTER_DISABLE_MITM=true` እና
   `NINEROUTER_DISABLE_TUNNEL=true` ሂደቱ ሲጀመር በሚተላለፈው አካባቢ ውስጥ መኖራቸውን ያረጋግጡ (`installers/ninerouter.ts` ውስጥ ያለውን `resolveSpawnArgs` ይመልከቱ)።

## 8. ተደጋግመው የሚጠየቁ ጥያቄዎች

**ጥያቄ፦ የተካተቱትን የአገልግሎት መዳረሻዎች ለloopback ያልሆኑ ደንበኞች ማጋለጥ እችላለሁ?**

አይ። የLOCAL_ONLY ደረጃ ሆን ተብሎ የተቀየሰ ነው (ጥብቅ ደንብ #17)።
`npm install`ን ማስኬድ ወይም የ`node` ሂደቶችን መጀመር የሚችሉ መንገዶች
ከloopback ያልሆነ ትራፊክ ተደራሽ መሆን የለባቸውም፤ ምክንያቱም በመሿለኪያ
(Cloudflare, Ngrok, Tailscale) በኩል የወጣ JWT፣ ያለዚያ ማንኛውንም ሂደት
እንዲጀመር ይፈቅዳል። ለ`/api/services/` ከዚህ ደንብ ለመውጣት ምንም
ልዩ ሁኔታ የለም — ከ`/api/mcp/` በተለየ፣ ከmanage-scope ማለፊያ
ዝርዝር ውጭ ነው። `docs/security/ROUTE_GUARD_TIERS.md`ን ይመልከቱ።

---

**ጥያቄ፦ 9Router እና CLIProxyAPI በproduction/cloud ማሰማራቶች ውስጥ ይገኛሉ?**

አዎ። ሁለቱም አገልግሎቶች እንደ OmniRoute ራሱ በአካባቢያዊ አጠቃቀም ቅድሚያ
የሚሰጥ ሞዴልን ይከተላሉ። በተመሳሳዩ ማሽን ላይ ይሰራሉ እና በloopback
በኩል ይገናኛሉ። እዚህ ላይ "Production" ማለት OmniRoute የተሰማራበትን
VPS ወይም አካባቢያዊ ሰርቨር እንጂ የርቀት cloud አቅራቢን አይደለም።

---

**ጥያቄ፦ supervisorን እንዴት ነው ስህተት የምፈልግበት?**

1. የSSE ምዝግብ ዥረቱን ይከታተሉ፦ `curl -N http://localhost:20128/api/services/9router/logs`።
2. በ`service:supervisor` namespace የተጣሩትን በOmniRoute pino ውጤት ውስጥ
   ያሉ የተዋቀሩ ምዝግቦች ያረጋግጡ።
3. የDB ረድፉን ይመርምሩ፦ `sqlite3 ~/.omniroute/omniroute.db "SELECT * FROM version_manager WHERE tool='9router'"`።
4. የአሁኑን ቀጥታ ሁኔታ፣ PID፣ ጤና እና `lastError`ን በአንድ ጥሪ
   ለማየት `GET /api/services/9router/status`ን ይጠቀሙ።

---

**ጥያቄ፦ supervisor `health: "degraded"` ወይም `health: "unknown"` ያሳያል፣ ነገር ግን ሁኔታው `"running"` ነው። ይህ ችግር ነው?**

`"degraded"` ማለት የጤና ምርመራው 200 ያልሆነ ምላሽ መልሷል ማለት ነው።
`"unknown"` ማለት እስካሁን ምንም ምርመራ አልተጠናቀቀም ማለት ነው
(ከመጀመሪያው ምርመራ ጋር ያለ የጊዜ ውድድር)። ሁለቱም በመነሻ ጊዜ
ጊዜያዊ ናቸው። ከ`"running"` በኋላ ከ`healthIntervalMs * 3` ms በላይ
ጤናው `"degraded"` ሆኖ ከቀጠለ፣ የተካተተው አገልግሎት እየሰራ ነው፣
ነገር ግን HTTP APIው ምላሽ እየሰጠ አይደለም። በሁኔታ ምላሹ ውስጥ
portን ትክክል መሆኑን እና አገልግሎቱ በእርግጥ በዚያ port ላይ እያዳመጠ
መሆኑን ያረጋግጡ።

---

**ጥያቄ፦ ሙሉ በሙሉ ዳግም ሳላስጀምር የ9Router API ቁልፍን መቀየር እችላለሁ?**

አይ። API ቁልፉ ሂደቱ በሚጀመርበት ጊዜ በenvironment variable በኩል ወደ
9Router ይተላለፋል። Environment variables በሚሰራ ሂደት ውስጥ ሊቀየሩ
አይችሉም። `POST .../rotate-key` አዲሱን ቁልፍ ተግባራዊ ለማድረግ አገልግሎቱን
በራስ-ሰር ያቆማል እና ዳግም ያስጀምራል። የቁልፉ ማዞር በአገልግሎቱ
`stopTimeoutMs` (ነባሪው 15 s) እና በመነሻ ጊዜው ድምር ውስጥ ተግባራዊ
ይሆናል።

---

**ጥያቄ፦ የring buffer ገደቡ ስንት ነው፣ ሲሞላስ ምን ይከሰታል?**

እያንዳንዱ አገልግሎት ራሱን የቻለ 5 MB ring buffer አለው። buffer ሲሞላ፣
ለአዳዲስ የምዝግብ መስመሮች ቦታ ለመስጠት ከሁሉም የቆዩት የምዝግብ
መስመሮች ይወገዳሉ። የSSE `snapshot` ክስተት በ`tail` ገደብ ውስጥ ያሉትን
በጣም የቅርብ ጊዜ መስመሮች ይመልሳል። `logsBufferPath` በDB ረድፍ ውስጥ
ካልተዋቀረ በስተቀር ምዝግቦች በዲስክ ላይ አይቀመጡም።
