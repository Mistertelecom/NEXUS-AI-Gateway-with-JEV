## 1. সংক্ষিপ্ত বিবরণ

### এমবেডেড সার্ভিস কেন?

পাঁচটি সার্ভিস এমবেড করা আছে:

| সার্ভিস         | npm প্যাকেজ                       | ডিফল্ট পোর্ট | উদ্দেশ্য                                                                                                                                                                                              |
| --------------- | --------------------------------- | :----------: | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **9Router**     | `9router`                         |    20130     | AI রাউটার, যা OmniRoute একটি সাব-প্রোভাইডার হিসেবে ব্যবহার করতে পারে। মডেলগুলো `9router/{sub}/{model}` হিসেবে উন্মুক্ত করা হয়                                                                        |
| **CLIProxyAPI** | GitHub রিলিজ বাইনারি (`cliproxy`) |     8317     | Anthropic CLI auth flow-এর জন্য স্থানীয় প্রক্সি অ্যাডাপ্টার। OAuth token-এর মেয়াদ শেষ হলে ফলব্যাক রাউটিং প্রদান করে                                                                                 |
| **Mux**         | `mux` (হেডলেস `mux server`)       |     8322     | স্থানীয় এজেন্ট-অর্কেস্ট্রেশন ডেমন (coder/mux)। শুধু লাইফসাইকেল ব্যবস্থাপিত — রাউটিং টার্গেট নয় (কোনো LLM প্রক্সিং নেই)।                                                                             |
| **Bifrost**     | `@maximhq/bifrost`                |     8080     | Go AI-gateway রিলে ব্যাকএন্ড। চলমান থাকলে রিলে রুট (`/v1/relay/`) স্বয়ংক্রিয়ভাবে এটি নির্বাচন করে                                                                                                   |
| **Dario**       | `@askalf/dario`                   |     3456     | Claude-subscription প্রক্সি — Claude-Code-আকৃতির ট্রাফিকের জন্য CLIProxyAPI-এর বিকল্প/ফেইলওভার; ইনজেক্ট করা key-টি `DARIO_ADMIN_TOKEN` হয়ে এর `/admin/*` OAuth control plane-এ প্রবেশ নিয়ন্ত্রণ করে |

পাঁচটিই একই তত্ত্বাবধান মডেল অনুসরণ করে:

- OmniRoute এগুলোকে `DATA_DIR/services/{name}/`-এর অধীনে ইনস্টল করে (OmniRoute-এর নিজস্ব `package.json` থেকে বিচ্ছিন্ন)
- OmniRoute এগুলোকে child process হিসেবে চালু ও পর্যবেক্ষণ করে
- OmniRoute child process-এর environment-এ একটি অস্থায়ী API key ইনজেক্ট করে এবং ডাউনটাইম ছাড়াই সেটি পরিবর্তন করে (যেখানে প্রযোজ্য)
- সব ব্যবস্থাপনা রুট (`/api/services/*`) **LOCAL_ONLY** — শুধু loopback থেকে অ্যাক্সেসযোগ্য (কঠোর নিয়ম #17)

### মূল সিদ্ধান্তসমূহ (ডিজাইন পরিকল্পনা থেকে)

| সিদ্ধান্ত                                         | মান                                                                                              |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 9Router-এর নিজস্ব UI-তে ড্যাশবোর্ডের প্রবেশাধিকার | `/dashboard/providers/services/9router/embed/*`-এ reverse proxy                                  |
| ইনস্টলেশন পদ্ধতি                                  | `execFile`-এর মাধ্যমে `npm install {package}` (কোনো shell interpolation নয়)                     |
| ব্যবহারের ধরন                                     | রাউটিং ইঞ্জিনে `9router/{sub}/{model}` হিসেবে নিবন্ধিত প্রোভাইডার                                |
| API key ব্যবস্থাপনা                               | OmniRoute তৈরি করে, সংরক্ষিত অবস্থায় এনক্রিপ্ট করে (AES-256-GCM) এবং env-এর মাধ্যমে ইনজেক্ট করে |
| ড্যাশবোর্ডের অবস্থান                              | `/dashboard/providers/services` (তিনটি ট্যাব)                                                    |
| স্বয়ংক্রিয়ভাবে চালু হওয়া                       | প্রতিটি সার্ভিসের জন্য toggle, ডিফল্টভাবে OFF                                                    |

```
└──────────────────────┬─────────────────────────────────────────────┘

│                                                                    │
│  open-sse/executors/ninerouter.ts                                  │
│    প্রতি অনুরোধে পোর্ট ও API কী পুনরায় খোঁজে (ক্যাশিং নেই)।      │

│                                                                    │
│  src/shared/constants/providers.ts                                 │
│    "9router"-এর এন্ট্রি: isEmbeddedService: true                   │
│                                                                    │
│  open-sse/config/providerRegistry.ts                               │
│    মডেলগুলো "9router/{sub}/{model}" হিসেবে সংরক্ষিত হয় (প্রিফিক্সযুক্ত)।│
│    modelSync.ts দ্বারা প্রতি 5 মিনিটে সিঙ্ক করা হয়।               │
│                                                                    │
│  Mux শুধু লাইফসাইকেল-পরিচালিত (স্তর 1-3) — এটি একটি এজেন্ট-       │
│  অর্কেস্ট্রেশন ডেমন, LLM প্রক্সি নয়; তাই এর কোনো স্তর 4           │
│  executor/provider এন্ট্রি নেই এবং এটি কখনোই রাউটিং লক্ষ্য নয়।   │
└────────────────────────────────────────────────────────────────────┘
```

### মূল সোর্স ফাইলসমূহ

| ফাইল                                        | ভূমিকা                                          |
| ------------------------------------------- | ----------------------------------------------- |

| `src/lib/services/bootstrap.ts`             | প্রসেস-স্তরের নিবন্ধন এবং স্বয়ংক্রিয় সূচনা    |

| `src/lib/services/ringBuffer.ts`            | SSE সাবস্ক্রাইবসহ ৫ MB সার্কুলার লগ বাফার       |

## 3. লাইফসাইকেল স্টেট মেশিন

```
                    install()
  ┌─────────────┐ ──────────► ┌─────────────┐
  │ not_installed│             │   stopped   │◄──────────────────┐
  └─────────────┘             └──────┬──────┘                   │
                                     │ start()                   │
                                     ▼                           │ stop()
                               ┌──────────┐                      │
                               │ starting │                      │
                               └────┬─────┘                     │
             হেলথ প্রোব সফল হয়েছে │         ক্র্যাশ / SIGTERM    │
                               ┌────▼─────┐  (5s-এর মধ্যে প্রস্থান)│
                               │ running  │──── ক্র্যাশ ─────────►┤
                               └────┬─────┘                   ┌─▼────┐
                             stop() │                          │error │
                                    ▼                          └──────┘
                               ┌──────────┐
                               │ stopping │
                               └──────────┘
```

স্টেটগুলো `version_manager` DB টেবিলে (`status` কলাম) সংরক্ষিত থাকে এবং
`ServiceSupervisor`-এর ইন-মেমরি স্টেটে প্রতিফলিত হয়। চলমান প্রসেসের ক্ষেত্রে
ইন-মেমরি স্টেটই চূড়ান্ত কর্তৃত্বপূর্ণ; বুটের সময় DB স্টেটটি টেকসই ফলব্যাক হিসেবে ব্যবহৃত হয়।

### স্টেট ট্রানজিশন

| যেখান থেকে      | ইভেন্ট                                  | যেখানে যাবে             |
| --------------- | --------------------------------------- | ----------------------- |
| `not_installed` | `install()` সফল হয়                     | `stopped`               |
| `stopped`       | `start()` কল করা হয়                    | `starting`              |
| `starting`      | হেলথ প্রোব 200 ফেরত দেয়                | `running`               |
| `starting`      | সুস্থ হওয়ার আগেই প্রসেস বন্ধ হয়       | `error`                 |
| `running`       | `stop()` কল করা হয়                     | `stopping` → `stopped`  |
| `running`       | প্রসেস অপ্রত্যাশিতভাবে বন্ধ হয় (< 5 s) | `error` (দ্রুত ক্র্যাশ) |
| `running`       | প্রসেস অপ্রত্যাশিতভাবে বন্ধ হয় (> 5 s) | `error`                 |
| `error`         | `start()` কল করা হয়                    | `starting`              |
| যেকোনো          | `stopping` অবস্থায় `stop()`            | কোনো কার্যক্রম নয়      |

### অপারেশন লক

`ServiceSupervisor` একটি অ্যাসিঙ্ক অপারেশন লকের (`withLock()`) মাধ্যমে লাইফসাইকেল
অপারেশনগুলোকে ধারাবাহিকভাবে সম্পাদন করে। একই সুপারভাইজরে একযোগে `start()` কল করা হলে
ঠিক একটি স্পন ঘটে; দ্বিতীয় কলকারী অপেক্ষা করে এবং বিদ্যমান স্ট্যাটাস ফেরত পায়। উদাহরণস্বরূপ,
অটো-স্টার্ট এবং কোনো UI বোতাম একই সময়ে সক্রিয় হলে এটি রেস কন্ডিশন প্রতিরোধ করে।

## 4. API রেফারেন্স

`/api/services/`-এর অধীন সব রুট **LOCAL_ONLY** (শুধু লুপব্যাক, কঠোর নিয়ম #17)।
অথ টোকেন নির্বিশেষে নন-লুপব্যাক রিকোয়েস্ট `403 LOCAL_ONLY` পায়।

### 4.1 9Router এন্ডপয়েন্টসমূহ (11টি রুট)

#### `POST /api/services/9router/install`

npm থেকে 9Router ইনস্টল করে। নিজস্ব `package.json` এবং `node_modules/`-সহ
`DATA_DIR/services/9router/` তৈরি করে। এটি OmniRoute-এর নিজস্ব ডিপেন্ডেন্সির সঙ্গে
সংঘর্ষ সৃষ্টি করে না।

**রিকোয়েস্ট বডি** (সবগুলো ঐচ্ছিক):

```json
{ "version": "latest" }
```

| ফিল্ড     | ধরন      | ডিফল্ট     | বিবরণ                                       |
| --------- | -------- | ---------- | ------------------------------------------- |
| `version` | `string` | `"latest"` | ইনস্টল করার জন্য npm ভার্সন ট্যাগ বা semver |

**রেসপন্সসমূহ:**

| স্ট্যাটাস | বিবরণ                                                          |
| --------- | -------------------------------------------------------------- |
| `200`     | `{ ok: true, installedVersion: "x.y.z", path: "..." }`         |
| `400`     | অবৈধ রিকোয়েস্ট বডি (Zod ভ্যালিডেশন ব্যর্থতা)                  |
| `409`     | ইতোমধ্যে ইনস্টল করা হচ্ছে (লক অধিগৃহীত)                        |
| `500`     | npm ইনস্টল ব্যর্থ — ব্যবহারবান্ধব ত্রুটির জন্য `message` দেখুন |

**নোট:** `execFile('npm', [...])` ব্যবহার করে — কোনো শেল বা ইন্টারপোলেশন নেই (কঠোর নিয়ম #13)।
EACCES ত্রুটিগুলো ব্যবহারবান্ধব বার্তা হিসেবে দেখানো হয়।

---

#### `POST /api/services/9router/start`

9Router চালু করে। আগে থেকে নিবন্ধিত না থাকলে একটি সুপারভাইজর নিবন্ধন করে, তারপর
`supervisor.start()` কল করে। আগে থেকেই চলমান থাকলে এটি আইডেমপোটেন্ট।

**রিকোয়েস্ট বডি:** নেই

**রেসপন্সসমূহ:**

| স্ট্যাটাস | বিবরণ                                                      |
| --------- | ---------------------------------------------------------- |
| `200`     | `ServiceStatus` অবজেক্ট (নিচের স্কিমা দেখুন)               |
| `409`     | 9Router ইনস্টল করা নেই (`status: "not_installed"`)         |
| `503`     | চালু করা ব্যর্থ হয়েছে (প্রসেস ত্রুটি — `lastError` দেখুন) |

**ServiceStatus স্কিমা:**

```json
{
  "tool": "9router",
  "state": "running",
  "pid": 12345,
  "port": 20130,
  "health": "healthy",
  "startedAt": "2026-05-25T10:00:00.000Z",
  "lastError": null
}
```

#### `POST /api/services/9router/stop`

9Router স্বাভাবিকভাবে বন্ধ করে। SIGTERM পাঠায়, 15 s অপেক্ষা করে, তারপরও চালু থাকলে
SIGKILL পাঠায়। আগে থেকেই বন্ধ থাকলে এটি আইডেমপোটেন্ট।

**রিকোয়েস্ট বডি:** নেই

**রেসপন্সসমূহ:**

| স্ট্যাটাস | বিবরণ                                  |
| --------- | -------------------------------------- |
| `200`     | `ServiceStatus` (`state: "stopped"`)   |
| `503`     | অপ্রত্যাশিতভাবে বন্ধ করা ব্যর্থ হয়েছে |

#### `POST /api/services/9router/restart`

অপারেশন লকের অধীনে প্রথমে `stop()` এবং তারপর `start()` করার সমতুল্য।

**রিকোয়েস্ট বডি:** নেই

**রেসপন্সসমূহ:** `start`-এর মতোই (চূড়ান্ত `ServiceStatus` ফেরত দেয়)।

#### `POST /api/services/9router/update`

9Router-কে আরও নতুন npm ভার্সনে আপডেট করে। সার্ভিসটি চলমান থাকলে প্রথমে সেটি বন্ধ করা হয়,
তারপর npm ইনস্টল চালানো হয় (নতুন ভার্সনটি একই স্থানে ইনস্টল করা হয়), এবং এরপর
সার্ভিসটি পুনরায় চালু করা হয়।

**রিকোয়েস্ট বডি** (সবগুলো ঐচ্ছিক):

```json
{ "version": "latest" }
```

**রেসপন্সসমূহ:**

| স্ট্যাটাস | বিবরণ                                                           |
| --------- | --------------------------------------------------------------- |
| `200`     | `{ ok: true, previousVersion: "...", installedVersion: "..." }` |
| `400`     | অবৈধ বডি                                                        |
| `500`     | npm আপডেট ব্যর্থ                                                |

#### `POST /api/services/9router/rotate-key`

9Router-এর জন্য একটি নতুন API কী তৈরি করে, সংরক্ষিত অবস্থায় সেটি এনক্রিপ্ট করে এবং সার্ভিসটি
চালু থাকলে পুনরায় চালু করে, যাতে এটি পরিবেশ থেকে নতুন কীটি গ্রহণ করে। পুরোনো কীটি
তাৎক্ষণিকভাবে অকার্যকর করা হয়।

**রিকোয়েস্ট বডি:** নেই

**রেসপন্সসমূহ:**

| স্ট্যাটাস | বিবরণ                                      |
| --------- | ------------------------------------------ |
| `200`     | `{ keyRotated: true, restarted: boolean }` |
| `500`     | কী রোটেশন ব্যর্থ হয়েছে                    |

**নিরাপত্তা:** নতুন কীটি কখনোই রেসপন্সে ফেরত দেওয়া হয় না (ক্রেডেনশিয়াল ফাঁস হয় না)।
এটি `version_manager` টেবিলে এনক্রিপ্ট করা অবস্থায় (AES-256-GCM) সংরক্ষিত থাকে।

#### `GET /api/services/9router/logs`

9Router-এর stdout/stderr রিং বাফার থেকে লাইভ লগের SSE স্ট্রিম।

**কোয়েরি প্যারামিটারসমূহ:**

| প্যারামিটার | ধরন       | ডিফল্ট | বিবরণ                                                        |
| ----------- | --------- | ------ | ------------------------------------------------------------ |

| `filter`    | `string`  | নেই    | কেস-ইনসেনসিটিভ সাবস্ট্রিং ফিল্টার (regex নয় — ReDoS-নিরাপদ) |

**SSE ইভেন্টসমূহ:**

| ইভেন্ট      | ডেটা        | বিবরণ                     |
| ----------- | ----------- | ------------------------- |
| `snapshot`  | `LogLine[]` | প্রাথমিক ঐতিহাসিক শেষাংশ  |
| `log`       | `LogLine`   | লাইভ লগ লাইন              |
| `heartbeat` | `{}`        | প্রতি 15 s-এ কিপ-অ্যালাইভ |

**LogLine স্কিমা:**

```json
{
  "ts": 1716633600000,
  "stream": "stdout",
  "line": "[9router] Listening on :20130"
}
```

**রেসপন্সসমূহ:**

| স্ট্যাটাস | বিবরণ                                              |
| --------- | -------------------------------------------------- |
| `200`     | `text/event-stream`                                |
| `400`     | `filter` প্যারামিটারটি অত্যন্ত দীর্ঘ (> 200 অক্ষর) |
| `404`     | সার্ভিস পাওয়া যায়নি (সুপারভাইজার নিবন্ধিত নয়)   |

### 4.2 CLIProxyAPI এন্ডপয়েন্টসমূহ (10টি রুট)

CLIProxyAPI-এর এন্ডপয়েন্ট কাঠামো 9Router-এর মতোই, তবে `rotate-key` নেই এবং এর সঙ্গে
`accounts`, `provider-expose` ও `auto-restart-adopted` রয়েছে। এটি এখন স্পন করার সময়
ইনজেক্ট করা একটি নিবেদিত ডেটা-প্লেন API কী পায় (`bootstrap.ts`-এ `needsApiKey: true`,
যা মডেল সিঙ্কের জন্য ব্যবহৃত হয়); `status`-এ তুলনামূলকভাবে কম ফিল্ড থাকে।

| মেথড   | পাথ                                 | বিবরণ                                      |
| ------ | ----------------------------------- | ------------------------------------------ |
| `POST` | `/api/services/cliproxy/install`    | npm থেকে CLIProxyAPI ইনস্টল করে            |
| `POST` | `/api/services/cliproxy/start`      | CLIProxyAPI চালু করে                       |
| `POST` | `/api/services/cliproxy/stop`       | CLIProxyAPI বন্ধ করে                       |
| `POST` | `/api/services/cliproxy/restart`    | CLIProxyAPI পুনরায় চালু করে               |
| `POST` | `/api/services/cliproxy/update`     | অপেক্ষাকৃত নতুন ভার্সনে আপডেট করে          |
| `GET`  | `/api/services/cliproxy/status`     | লাইভ + DB স্ট্যাটাস (`apiKeyMasked` ছাড়া) |
| `POST` | `/api/services/cliproxy/auto-start` | স্বয়ংক্রিয়ভাবে চালু হওয়া টগল করে        |

শেয়ার করা `GET /api/services/{name}/logs` এন্ডপয়েন্টটি (§4.1 দেখুন) `[name]`
ডায়নামিক সেগমেন্ট ব্যবহার করে চারটি সার্ভিসের সবগুলোর জন্য কাজ করে।

### 4.3 Mux এন্ডপয়েন্টসমূহ (8টি রুট)

### 4.6 রিভার্স প্রক্সি (9Router ড্যাশবোর্ড এম্বেড)

ড্যাশবোর্ডটি একটি অভ্যন্তরীণ রিভার্স প্রক্সির মাধ্যমে iframe-এর ভেতরে 9Router ওয়েব UI
এম্বেড করে:

```
GET|POST|... /dashboard/providers/services/9router/embed/[...path]
```

এই প্রক্সি:

- অনুরোধটি `http://127.0.0.1:{port}/{path}`-এ ফরোয়ার্ড করে (শুধু লুপব্যাক)
- ইনকামিং `cookie` এবং `authorization` হেডার বাদ দেয় (OmniRoute সেশন ফাঁস হয় না)
- 9Router প্রমাণীকরণের জন্য `Authorization: Bearer {apiKey}` ইনজেক্ট করে
- রেসপন্স থেকে `set-cookie`, `content-security-policy`, `x-frame-options`, `cross-origin-*` বাদ দেয়
- `<base href>` ইনজেক্ট করতে এবং অ্যাবসোলিউট পাথগুলো স্বাভাবিক করতে HTML রেসপন্স পুনর্লিখন করে (`/foo` → `/dashboard/.../embed/foo`)

এম্বেড করা ড্যাশবোর্ডের WebSocket আপগ্রেডগুলো একটি
নির্ধারিত পোর্টে থাকা সহযোগী সার্ভার দ্বারা পরিচালিত হয় (`src/lib/services/embedWsProxy.ts` দেখুন)।

**নিরাপত্তা:** এম্বেড প্রক্সি রুটগুলো `LOCAL_ONLY_API_PREFIXES`-এর অধীনে শ্রেণিবদ্ধ
এবং কেবল লুপব্যাক থেকে অ্যাক্সেস করা যায়। Cloudflare/Ngrok টানেলের মাধ্যমে JWT পাওয়া কোনো
আক্রমণকারী এম্বেড করা সার্ভিসগুলোতে প্রক্সি করতে পারবে না।

## 5. নিরাপত্তা

### LOCAL_ONLY প্রয়োগ (কঠোর নিয়ম #17)

`/api/services/` এবং `/dashboard/providers/services/*/embed/`-এর অধীনে থাকা সব রুটকে
`src/server/authz/routeGuard.ts`-এ LOCAL_ONLY হিসেবে শ্রেণিবদ্ধ করা হয়েছে। যেকোনো auth শাখার আগে
loopback পরীক্ষা নিঃশর্তভাবে চালানো হয়:

```
অনুরোধ আসে
  → isLocalOnlyPath(path)?
      → non-loopback → 403 LOCAL_ONLY (সবসময়, auth পরীক্ষার আগে)
      → loopback     → স্বাভাবিক auth প্রক্রিয়ায় অগ্রসর হয়
```

এটি কোনো ফাঁস হওয়া JWT-কে (যেমন, কোনো tunnel-এর মাধ্যমে) `npm install` চালু করা বা
process spawn করা থেকে বিরত রাখে। সম্পূর্ণ tier
matrix-এর জন্য `docs/security/ROUTE_GUARD_TIERS.md` দেখুন।

### API key ইনজেকশন

9Router এবং Mux-এর নিজস্ব HTTP endpoint-এর জন্য একটি API key/bearer token প্রয়োজন।
OmniRoute:

1. `crypto.randomBytes(32).toString("base64url")`-এর মাধ্যমে একটি key তৈরি করে, যার সঙ্গে
   service-নির্দিষ্ট prefix থাকে (9Router-এর জন্য `nr_`, Mux-এর জন্য `mx_`)।
2. AES-256-GCM ব্যবহার করে এটিকে at-rest অবস্থায় encrypt করে (provider credential-এর জন্য ব্যবহৃত একই cipher)।
3. Spawn করার সময় এটিকে decrypt করে environment variable হিসেবে inject করে —
   9Router-এর জন্য `NINEROUTER_API_KEY`, Mux-এর জন্য `MUX_SERVER_AUTH_TOKEN` (কখনোই CLI
   flag হিসেবে নয়, তাই token কখনো `ps`/process listing-এ দেখা যায় না)।
4. কোনো HTTP response-এ কখনো plaintext key ফেরত দেয় না।

CLIProxyAPI spawn করার সময় একটি নিবেদিত data-plane key পায়
(`needsApiKey: true` — adapter-এর বিপরীতে model sync-এর জন্য ব্যবহৃত)।

### SSRF প্রতিরক্ষা

Reverse HTTP proxy (`/dashboard/.../embed/[...path]`) কেবল
`http://127.0.0.1:{port}`-এ forward করার জন্য hardcode করা। এটি কখনো non-loopback
গন্তব্যে redirect অনুসরণ করে না। Loopback range-এর বাইরে resolve হওয়া যেকোনো upstream URL
প্রত্যাখ্যান করতে `ssrf-req-filter` library ব্যবহার করা হয়।

### Shell নিরাপত্তা (কঠোর নিয়ম #13)

`npm install`-কে `execFile('npm', ['install', pkg, '--prefix', dir])`-এর মাধ্যমে invoke করা হয় —
কোনো template literal বা shell ব্যবহার করা হয় না এবং command
string-এ external path interpolate করা হয় না। Runtime value (port, API key) child-এর `env` object-এর মাধ্যমে পাঠানো হয়।

### Error স্যানিটাইজেশন (কঠোর নিয়ম #12)

`/api/services/*` থেকে আসা সব error response `buildErrorBody()` অথবা
`sanitizeErrorMessage()`-এর মধ্য দিয়ে যায়। Raw `err.stack` এবং `err.message` কখনোই
হুবহু caller-এর কাছে ফেরত দেওয়া হয় না।

## 6. নতুন embedded service যোগ করা

এই 8টি ধাপ অনুসরণ করুন। Canonical reference হিসেবে `src/lib/services/installers/`
এবং `src/app/api/services/`-এর বিদ্যমান implementation-গুলো পড়ুন।

### ধাপ 1 — Installer তৈরি করুন

`ninerouter.ts` অনুসরণ করে `src/lib/services/installers/{name}.ts` তৈরি করুন:

```typescript
export const NAME_PACKAGE = "your-npm-package";
export const NAME_DEFAULT_PORT = 20132; // একটি খালি port বেছে নিন

export async function install(version = "latest"): Promise<InstallResult> { ... }
export async function update(version = "latest"): Promise<InstallResult> { ... }
export async function uninstall(): Promise<void> { ... }
export function resolveSpawnArgs(apiKey: string, port: number): SpawnArgs { ... }
export async function getInstalledVersion(): Promise<string | null> { ... }
export async function getLatestVersion(): Promise<string | null> { ... }
```

`installers/utils.ts` থেকে `runNpm(['install', NAME_PACKAGE, '--prefix', dir])` ব্যবহার করুন
— কখনোই `execSync` বা shell interpolation ব্যবহার করবেন না।

### ধাপ 2 — Bootstrap-এ নিবন্ধন করুন

`src/lib/services/bootstrap.ts`-এর `SERVICES` array-তে একটি `ServiceEntry` যোগ করুন:

```typescript
{
  tool: "myservice",
  port: NAME_DEFAULT_PORT,
  healthPath: "/health",
  healthIntervalMs: 5_000,
  stopTimeoutMs: 15_000,
  logsBufferBytes: 5_242_880,
  needsApiKey: true, // API key প্রয়োজন না হলে false
}
```

`cfg.tool === "myservice"` পরিচালনা করতে `buildSpawnArgsFactory()` প্রসারিত করুন।

#### Pluggable provider-plugin contract (Phase 1, #7333)

`src/lib/services/providerPlugins/` একটি `ServiceProviderPlugin` contract প্রবর্তন করে, যা
একটি backend-এর `bootstrap.ts`-এর `ServiceEntry` field এবং `serviceBackends.ts`-এর
manifest-template field-কে একটি object-এ প্যাকেজ করে; একই backend-এর কাঠামোকে দুটি সম্পর্কহীন
file-এ আলাদাভাবে প্রকাশ করার পরিবর্তে। এটি লেখার সময় পর্যন্ত **শুধু `9router`
migrate করা হয়েছে** — `bootstrap.ts`, `getServiceProviderPlugin("9router")`
(`src/lib/services/providerPlugins/registry.ts`) থেকে তার `SERVICES[]` entry তৈরি করে;
plugin কখনো অনুপস্থিত থাকলে একটি startup error throw করে। `cliproxy`, `mux`, এবং `bifrost`
অপরিবর্তিতভাবে আগে থেকে বিদ্যমান inline `SERVICES[]` literal-এই রয়েছে।

`open-sse/config/providerPluginManifest.ts`-এ একটি additive
`createServiceBackendManifestEntry(pluginId, template)` helper-ও যোগ করা হয়েছে, যা একটি
`SERVICE_BACKEND_MANIFEST_TEMPLATE` entry থেকে একটি সুগঠিত
`ProviderPluginManifestEntry` তৈরি করে — এটি এখনো কোনো live request path-এর সঙ্গে
সংযুক্ত **নয়** (`generateProviderPluginManifestFromRegistry()`-ও নয়,
`/v1/providers/[provider]/models`-ও নয়); দ্বিতীয় কোনো backend-এর জন্য contractটি
প্রমাণিত হলে এটি follow-up হিসেবে করা হবে।

Follow-up PR-এ স্থগিত রাখা হয়েছে এবং issue #7333-এর অধীনে track করা হচ্ছে:
একই registry-এর মাধ্যমে `cliproxyapi` migrate করা, `mux`/`bifrost`-কে
`ServiceBackendPluginId` union-এ generalize করা, executor-routing-এর বিশেষ handling
(`open-sse/executors/index.ts`, `open-sse/handlers/chatCore/executorProxy.ts`)-কে
plugin contract-এর মধ্যে অন্তর্ভুক্ত করা এবং `createServiceBackendManifestEntry()`-কে
একটি live manifest/models code path-এর সঙ্গে সংযুক্ত করা।

### ধাপ 3 — Migration এবং DB seed যোগ করুন

`src/lib/db/migrations/`-এর একটি migration-এর মাধ্যমে নিশ্চিত করুন যে serviceটির
`version_manager`-এ একটি row রয়েছে। Row-টি এমন হওয়া উচিত:

### ধাপ 4 — 7টি API endpoint তৈরি করুন

`src/app/api/services/{name}/`-এর অধীনে:

```
_lib.ts            getOrInitSupervisor() helper
install/route.ts   POST — installer.install() call করে
start/route.ts     POST — supervisor.start() call করে
stop/route.ts      POST — supervisor.stop() call করে
restart/route.ts   POST — supervisor.restart() call করে
update/route.ts    POST — installer.update() call করে
status/route.ts    GET  — live + DB status একত্রিত করে

```

শেয়ার করা `GET /api/services/[name]/logs` রুটটি ইতিমধ্যেই সংযুক্ত করা আছে — সেখানে কোনো পরিবর্তনের
প্রয়োজন নেই।

সব ত্রুটি প্রতিক্রিয়া `createErrorResponse()` / `buildErrorBody()`-এর মাধ্যমে পরিচালনা করুন।

### ধাপ 5 — LOCAL_ONLY_API_PREFIXES-এ যোগ করুন

`src/server/authz/routeGuard.ts`-এ যাচাই করুন যে `/api/services/` ইতিমধ্যেই তালিকাভুক্ত আছে।
আপনি যদি একটি নতুন প্রিফিক্স (যেমন, `/api/tools/`) প্রবর্তন করেন, তবে সেটি
`LOCAL_ONLY_API_PREFIXES` এবং, যদি সেটি প্রসেস চালু করে, `SPAWN_CAPABLE_PREFIXES`—উভয়টিতেই যোগ করুন।
`tests/unit/authz/routeGuard.test.ts`-এ একটি টেস্ট যোগ করুন।

### ধাপ 6 — UI ট্যাব যোগ করুন

## 7. সমস্যা সমাধান

### সার্ভিস চালু হয় না

**লক্ষণ:** Start বাটন 503 রিটার্ন করে, স্টেট `"error"` বা `"starting"` অবস্থায় থাকে।

**চেকলিস্ট:**

1. `GET /api/services/{name}/logs` পরীক্ষা করুন (অথবা ড্যাশবোর্ডের Logs প্যানেল)। `Error: ENOENT`, `address already in use`, বা `Cannot find module`-এর মতো লাইন খুঁজুন।
2. `npm` PATH-এ আছে কি না যাচাই করুন: OmniRoute যে ইউজার অ্যাকাউন্ট দিয়ে চলে, সেই একই অ্যাকাউন্ট থেকে `which npm` চালান।
3. সার্ভিসটি ইনস্টল করা আছে কি না যাচাই করুন: `installedVersion`-এর জন্য `GET /api/services/{name}/status` পরীক্ষা করুন। এটি `null` হলে, প্রথমে ইনস্টল চালান।
4. `DATA_DIR/services/{name}/node_modules/` বিদ্যমান এবং খালি নয় কি না পরীক্ষা করুন।
5. পরিশোধিত এক্সিটের কারণ জানতে স্ট্যাটাস রেসপন্সের `lastError` ফিল্ড পরীক্ষা করুন।

---

### কোল্ড স্টার্ট ধীর (> `running` অবস্থায় পৌঁছাতে 10 s)

**লক্ষণ:** `"running"` বা `"error"` অবস্থায় যাওয়ার আগে স্টেট দীর্ঘ সময় `"starting"` অবস্থায় থাকে।

**ব্যাখ্যা:** 9Router-এর কোল্ড স্টার্টে বড় ডিপেন্ডেন্সি ট্রি (DNS, টানেল, MITM মডিউল) ইমপোর্ট করা অন্তর্ভুক্ত। ডিফল্ট হেলথ ইন্টারভ্যাল 2 s এবং সুপারভাইজার টাইমআউট ঘোষণা করার আগে 3 বার চেষ্টা করে (তবে পোলিং চালিয়ে যায়)।

**সমাধান:** `healthIntervalMs` এবং `waitForHealthy` টাইমআউট (`healthIntervalMs * 3`) `bootstrap.ts`-এ কনফিগার করা যায়। যেসব সার্ভিসের স্টার্টআপে বেশি সময় লাগে, সেগুলোর জন্য `healthIntervalMs` বাড়িয়ে 5000 এবং `stopTimeoutMs` বাড়িয়ে 30 000 করুন।

---

### পোর্ট সংঘর্ষ (`EADDRINUSE`)

**লক্ষণ:** লগে `address already in use :::20130` দেখা যায়।

**কারণ:**

- অন্য একটি প্রসেস ইতিমধ্যে পোর্ট 20130 ব্যবহার করছে।
- আগের কোনো 9Router প্রসেস সম্পূর্ণভাবে বন্ধ হয়নি (জম্বি PID)।

**সমাধান:**

1. `.env`-এ `NINEROUTER_PORT` এনভায়রনমেন্ট ভ্যারিয়েবলের মাধ্যমে ডিফল্ট পোর্ট পরিবর্তন করুন।
2. সংঘর্ষ সৃষ্টিকারী প্রসেসটি খুঁজে বন্ধ করুন: `lsof -ti :20130 | xargs kill -9`।
3. `bootstrap.ts`-এ `port` ফিল্ডের মাধ্যমে প্রতিটি সার্ভিসের জন্য পোর্ট কনফিগার করা যায়।

**দ্রষ্টব্য:** OmniRoute-এর ডিফল্ট পোর্ট 20128-এর সঙ্গে সংঘর্ষ এড়াতে 9Router বিশেষভাবে ডিফল্ট পোর্ট 20130 ব্যবহার করে।

---

### ইনস্টলের সময় অনুমতি প্রত্যাখ্যাত (EACCES)

**লক্ষণ:** ইনস্টল 500 রিটার্ন করে, লগে `EACCES` বা `permission denied` দেখা যায়।

**কারণ:**

- OmniRoute প্রসেস `DATA_DIR` বা এর প্যারেন্ট ডিরেক্টরিতে লিখতে পারে না।
- ম্যাপ করা ভলিউমে লেখার অনুমতি ছাড়াই রুটলেস Docker-এর ভিতরে চালানো হচ্ছে।

**সমাধান:**

1. `DATA_DIR` পরীক্ষা করুন (ডিফল্ট: `~/.omniroute/`): `ls -la ~/.omniroute/`
2. নিশ্চিত করুন যে OmniRoute প্রসেসের ইউজারটি ডিরেক্টরিটির মালিক: `chown -R $USER ~/.omniroute/`
3. Docker-এ নিশ্চিত করুন যে কনটেইনার ইউজারের জন্য ভলিউম মাউন্টে সঠিক অনুমতি রয়েছে।

---

### আপডেট ব্যর্থ হয় (`npm install` টাইমআউট বা নেটওয়ার্ক ত্রুটি)

**লক্ষণ:** আপডেট `InstallError`-সহ 500 রিটার্ন করে, লগে নেটওয়ার্ক টাইমআউট দেখা যায়।

**চেকলিস্ট:**

1. npm রেজিস্ট্রিতে পৌঁছানো যাচ্ছে কি না নিশ্চিত করুন: `npm ping`।
2. কর্পোরেট প্রক্সি পরীক্ষা করুন: `npm config get proxy`, `npm config get https-proxy`।
3. ম্যানুয়ালি ইনস্টল করার চেষ্টা করুন: `npm install {package}@latest --prefix ~/.omniroute/services/{name}/`।
4. এয়ার-গ্যাপের পেছনে থাকলে, টারবলটি আগে থেকে ডাউনলোড করুন এবং `npm install /path/to/tarball.tgz` ব্যবহার করুন।

---

### চালু করার পরপরই সার্ভিস `"error"` স্টেট দেখায় (দ্রুত ক্র্যাশ)

**লক্ষণ:** 5 সেকেন্ডেরও কম সময়ে স্টেট `"starting"` থেকে `"error"`-এ পরিবর্তিত হয়। `lastError`-এ `"Fast crash (exited with code 1)"` দেখা যায়।

**চেকলিস্ট:**

1. সম্পূর্ণ লগ টেইল পড়ুন: `GET /api/services/{name}/logs?tail=500`।
2. সাধারণ কারণ: সার্ভিসের প্রত্যাশিত এনভায়রনমেন্ট ভ্যারিয়েবল অনুপস্থিত।
3. 9Router-এর জন্য: স্পন করার সময় পাস করা env-এ `NINEROUTER_DISABLE_MITM=true` এবং `NINEROUTER_DISABLE_TUNNEL=true` রয়েছে কি না যাচাই করুন (`installers/ninerouter.ts`-এর `resolveSpawnArgs` দেখুন)।

## 8. প্রায়শই জিজ্ঞাসিত প্রশ্নাবলি

**প্রশ্ন: আমি কি এম্বেডেড সার্ভিসগুলোর এন্ডপয়েন্ট নন-লুপব্যাক ক্লায়েন্টদের জন্য উন্মুক্ত করতে পারি?**

না। LOCAL_ONLY টিয়ারটি ইচ্ছাকৃতভাবে নির্ধারিত (অপরিবর্তনীয় নিয়ম #17)। যেসব রুট
`npm install` চালাতে বা `node` প্রসেস তৈরি করতে পারে, সেগুলো নন-লুপব্যাক
ট্রাফিক থেকে অ্যাক্সেসযোগ্য হওয়া উচিত নয়, কারণ অন্যথায় কোনো টানেলের (Cloudflare,
Ngrok, Tailscale) মাধ্যমে ফাঁস হওয়া JWT নির্বিচারে প্রসেস তৈরির সুযোগ দেবে।
`/api/services/`-এর জন্য এর বাইরে যাওয়ার কোনো বিকল্প ব্যবস্থা নেই — `/api/mcp/`-এর
বিপরীতে, এটি manage-scope বাইপাস তালিকা থেকে বাদ দেওয়া হয়েছে। দেখুন
`docs/security/ROUTE_GUARD_TIERS.md`।

---

**প্রশ্ন: প্রোডাকশন/ক্লাউড ডিপ্লয়মেন্টে কি 9Router এবং CLIProxyAPI উপলভ্য থাকবে?**

হ্যাঁ। উভয় সার্ভিসই OmniRoute-এর মতো একই লোকাল-ফার্স্ট মডেল অনুসরণ করে। এগুলো
একই মেশিনে চলে এবং লুপব্যাকের মাধ্যমে যোগাযোগ করে। এখানে "প্রোডাকশন" বলতে বোঝায়
সেই VPS বা লোকাল সার্ভার যেখানে OmniRoute ডিপ্লয় করা হয়েছে, কোনো রিমোট ক্লাউড
প্রোভাইডার নয়।

---

**প্রশ্ন: আমি কীভাবে সুপারভাইজার ডিবাগ করব?**

1. SSE লগ স্ট্রিম অনুসরণ করুন: `curl -N http://localhost:20128/api/services/9router/logs`।
2. `service:supervisor` নেমস্পেস দিয়ে ফিল্টার করা OmniRoute-এর pino আউটপুটে
   স্ট্রাকচার্ড লগ পরীক্ষা করুন।
3. DB সারিটি পরিদর্শন করুন: `sqlite3 ~/.omniroute/omniroute.db "SELECT * FROM version_manager WHERE tool='9router'"`।
4. বর্তমান লাইভ স্টেট, PID, হেলথ এবং `lastError` একবারেই দেখতে
   `GET /api/services/9router/status` ব্যবহার করুন।

---

**প্রশ্ন: সুপারভাইজার `health: "degraded"` বা `health: "unknown"` দেখায়, কিন্তু স্টেট হলো `"running"`। এটি কি কোনো সমস্যা?**

`"degraded"`-এর অর্থ হলো হেলথ প্রোব একটি non-200 রেসপন্স ফিরিয়েছে। `"unknown"`-এর
অর্থ হলো এখনো কোনো প্রোব সম্পন্ন হয়নি (প্রথম পোলের সঙ্গে রেস কন্ডিশন)। স্টার্টআপের
সময় উভয় অবস্থাই সাময়িক। `"running"` হওয়ার পর `healthIntervalMs * 3` ms-এর বেশি
সময় ধরে হেলথ `"degraded"` থাকলে, এম্বেডেড সার্ভিসটি চলছে কিন্তু এর HTTP API সাড়া
দিচ্ছে না। স্ট্যাটাস রেসপন্সে পোর্টটি সঠিক কি না এবং সার্ভিসটি সত্যিই ওই পোর্টে
লিসেন করছে কি না, তা পরীক্ষা করুন।

---

**প্রশ্ন: সম্পূর্ণ রিস্টার্ট ছাড়াই কি আমি 9Router API কী পরিবর্তন করতে পারি?**

না। প্রসেস তৈরির সময় একটি এনভায়রনমেন্ট ভেরিয়েবলের মাধ্যমে API কীটি 9Router-এ
পাঠানো হয়। চলমান প্রসেসে এনভায়রনমেন্ট ভেরিয়েবল পরিবর্তন করা যায় না।
`POST .../rotate-key` নতুন কী প্রয়োগ করতে স্বয়ংক্রিয়ভাবে সার্ভিসটি বন্ধ করে পুনরায়
চালু করে। কী রোটেশনটি সার্ভিসের `stopTimeoutMs` (ডিফল্ট 15 s) এবং এর স্টার্টআপ
সময়ের যোগফলের মধ্যে কার্যকর হয়।

---

**প্রশ্ন: রিং বাফারের সীমা কত এবং এটি পূর্ণ হলে কী ঘটে?**

প্রতিটি সার্ভিসের জন্য আলাদা 5 MB রিং বাফার রয়েছে। বাফার পূর্ণ হয়ে গেলে নতুন
লাইনের জন্য জায়গা করতে সবচেয়ে পুরোনো লগ লাইনগুলো বাদ দেওয়া হয়। SSE `snapshot`
ইভেন্টটি `tail` সীমার মধ্যে সবচেয়ে সাম্প্রতিক লাইনগুলো ফেরত দেয়। DB সারিতে
`logsBufferPath` সেট করা না থাকলে লগগুলো ডিস্কে সংরক্ষণ করা হয় না।
