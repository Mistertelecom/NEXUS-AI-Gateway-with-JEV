دو روش برای قرار دادن Cursor پشت OmniRoute بدون نشست IDE:

1. **ارائهدهندهی `cursor-api`** (کارت «Cursor API»، نام مستعار `cua`): یک
   ارائهدهنده مبتنی بر کلید API که کلید API کاربر Cursor را نگه میدارد
   (`crsr_…`، تولیدشده در `https://cursor.com/dashboard/api`). سپس هر کلاینت
   OmniRoute میتواند از طریق `/v1/chat/completions` و با نام
   `cursor-api/<model>` یا `cua/<model>` به مدلهای Cursor دسترسی پیدا کند؛
   همراه با لایههای معمول سهمیه، جایگزینی و ثبت گزارش. ارائهدهنده IDE
   (`cursor`، نشست OAuth/IDE) بدون تغییر باقی میماند.
2. **عبور مستقیم Cursor CLI**: Cursor CLI (`agent`) را به OmniRoute متصل کنید تا
   هر RPC که CLI ارسال میکند با یک کلید API متعلق به OmniRoute احراز هویت شود،
   با اعتبارنامهی یک اتصال `cursor-api` به Cursor ارسال گردد و در صفحه Logs
   ثبت شود.

## چرا کلید مبادله میشود

`api2.cursor.sh` یک کلید خام `crsr_…` را بهعنوان توکن Bearer رد میکند (401).
Cursor CLI ابتدا کلید را با درخواست POST به `/auth/exchange_user_api_key`
ارسال میکند و یک JWT نشست با اعتبار یکساعته دریافت میکند؛ `refreshToken`
برگرداندهشده همان `exp` را دارد، بنابراین تازهسازی بهمعنای مبادلهی مجدد
کلید است.
`open-sse/services/cursorApiKeyAuth.ts` این مبادله را انجام میدهد، برای هر کلید
یک توکن نشست را در حافظه پنهان نگه میدارد، پنج دقیقه پیش از انقضا دوباره آن را
مبادله میکند و هنگامی که Cursor پاسخ 401 میدهد، توکن ذخیرهشده را حذف میکند.
`CursorExecutor` درست پیش از باز کردن جریان بالادستی برای اتصالهای
`cursor-api` آن را فراخوانی میکند.

## ارائهدهندهی `cursor-api`

رجیستری: `open-sse/config/providers/registry/cursor/index.ts`
(`cursor_apiProvider`، `authType: "apikey"`، با همان `format`، `baseUrl` و
`models` مربوط به `cursor`). کارت کاتالوگ:
`src/shared/constants/providers/apikey/specialty-media.ts`. نگاشت اجراکننده:
`open-sse/executors/index.ts` (`"cursor-api"` / `cua` →
`new CursorExecutor("cursor-api")`).

داشبورد: Providers → Cursor API → Add API key.

REST:

```bash
curl -sS -X POST http://localhost:20128/api/providers \
  -H "Content-Type: application/json" \
  -d '{"provider":"cursor-api","name":"cursor-api-key","apiKey":"crsr_…","priority":1}'
```

سپس:

```bash
curl -sS http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <omniroute-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"cursor-api/auto","messages":[{"role":"user","content":"say PONG"}]}'
```

نکات:

- فهرست مدلها برای `cursor-api` از رجیستری ایستای Cursor گرفته میشود (همان
  فهرستی که ارائهدهنده IDE در حالت جایگزین از آن استفاده میکند)؛ نیازی به
  نصب `cursor-agent` روی میزبان OmniRoute نیست.
- `POST /api/providers/{id}/refresh-cursor` فقط برای ارائهدهنده IDE با نام
  `cursor` است؛ اتصالهای `cursor-api` نشست IDE برای تمدید ندارند.

## عبور مستقیم Cursor CLI

مسیر: `src/app/api/cursor-cli/[...path]/route.ts` →
`open-sse/handlers/cursorCliProxy.ts`. پیشوند `/api/cursor-cli/` در
`src/shared/constants/publicApiRoutes.ts` ثبت شده است، زیرا کنترلکننده احراز
هویت مختص خود را اعمال میکند:

| مسیر                                                                                                                         | احراز هویت مورد انتظار از CLI | کاری که OmniRoute انجام میدهد                                                                                                                                                  |
| ---------------------------------------------------------------------------------------------------------------------------- | ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `POST /auth/exchange_user_api_key`                                                                                           | `Bearer <OmniRoute API key>`  | کلید را اعتبارسنجی میکند، یک JWT یکساعته HS256 صادر میکند (که با `JWT_SECRET` امضا شده است) و آن را برمیگرداند                                                                 |
| همه مسیرهای دیگر (`/aiserver.v1.*`، `/agent.v1.AgentService/RunSSE`، `/aiserver.v1.BidiService/BidiAppend`، `/v1/traces`، …) | `Bearer <that JWT>`           | صادرکننده/مخاطب/انقضا را بررسی میکند، یک اتصال فعال `cursor-api` را انتخاب میکند، هدر Authorization را با توکن مبادلهشده Cursor جایگزین کرده و پاسخ را بهصورت جریان برمیگرداند |

CLI مقدار `exp` را از هر توکنی که دریافت میکند رمزگشایی میکند؛ بنابراین ارائه
یک توکن غیرشفاف باعث میشود پیش از تقریباً هر درخواست، مبادله را دوباره انجام
دهد. JWT صادرشده از این وضعیت جلوگیری میکند. پاسخ 401 از OmniRoute باعث
میشود CLI دوباره مبادله را انجام دهد.

### راهاندازی

1. یک کلید API برای OmniRoute بسازید (Dashboard → API keys) و یک اتصال
   `cursor-api` ایجاد کنید.
2. به CLI اعلام کنید برای جریان عامل از HTTP/1.1 استفاده کند. در
   `~/.cursor/cli-config.json`:

   ```json
   { "network": { "useHttp1ForAgent": true } }
   ```

   بدون این تنظیم، CLI نوبت عامل را از طریق HTTP/2 و روی یک میزبان عامل که
   جداگانه پیکربندی شده است باز میکند و فقط RPCهای صفحه کنترل از endpoint
   عبور میکنند.

3. CLI را در مقابل OmniRoute اجرا کنید:

   ```bash
   export CURSOR_API_ENDPOINT=http://localhost:20128/api/cursor-cli
   export CURSOR_API_KEY=<omniroute-api-key>
   agent -p --trust "Reply with exactly OK"
   ```

هر مرحله در Logs با ارائهدهنده `cursor-api`، نوع درخواست `cursor-cli` و مسیر
`/api/cursor-cli/<rpc>` ثبت میشود و به کلید API متعلق به OmniRoute و اتصالی
که آن را سرویسدهی کرده است نسبت داده میشود.

### حالتهای شکست

| وضعیت                                               | پاسخ به CLI                                    |
| --------------------------------------------------- | ---------------------------------------------- |
| کلید ناشناختهٔ OmniRoute و `REQUIRE_API_KEY=true`   | 401 `unauthenticated` هنگام تبادل              |
| `REQUIRE_API_KEY=false`                             | نشست ناشناس (همانند رفتار `/v1/*`)             |
| JWT نشست منقضیشده / خارجی / دستکاریشده              | 401، CLI دوباره تبادل را انجام میدهد           |
| کلید API متعلق به OmniRoute پس از تبادل لغو شده است | 401 در RPC بعدی                                |
| هیچ اتصال فعالی به `cursor-api` وجود ندارد          | 503 `unavailable`                              |
| Cursor کلید اتصال را رد میکند                       | 401 `unauthenticated`، نشست ذخیرهشده حذف میشود |
| بالادست در دسترس نیست                               | 502 `unavailable` (پیام پاکسازیشده)            |
| `JWT_SECRET` تنظیم نشده است                         | 503 هنگام تبادل                                |
