> کلیدهای runtime که رفتار OmniRoute را **بدون استقرار مجدد** تغییر میدهند.
> تمام فلگهای فهرستشده در اینجا در
> [`src/shared/constants/featureFlagDefinitions.ts`](../../src/shared/constants/featureFlagDefinitions.ts)
> تعریف شدهاند — منبع واحد حقیقت. داشبورد و REST API هر دو از
> آن فایل میخوانند، بنابراین جدول زیر بهگونهای تولید شده است که دقیقاً بهصورت 1:1 با آن مطابقت داشته باشد.

---

## فلگهای قابلیت چیستند

فلگ قابلیت یک کلید نامگذاریشده (از نوع boolean یا enum) است که مقدار آن را میتوان در
runtime تغییر داد و در پایگاه داده ذخیره کرد، بدون اینکه نیاز به استقرار مجدد فرایند باشد. هر
فلگ با یک `FeatureFlagDefinition` توصیف میشود که شامل `key`، `label`،
`description`، `category`، `defaultValue`، `type` و راهنمای `requiresRestart` است.

### ترتیب تعیین مقدار

**مقدار مؤثر** یک فلگ توسط
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) و با ترتیب
اولویت زیر تعیین میشود (بالاترین اولویت برنده است):

1. **بازنویسی DB** — مقداری که در جدول `key_value` و در فضای نام
   `feature_flags` ذخیره شده است (از طریق داشبورد یا REST API تنظیم میشود).
2. **متغیر محیطی** — `process.env[<KEY>]`، در صورتی که تنظیم شده و خالی نباشد.
3. **مقدار پیشفرض تعریف** — مقدار `defaultValue` از `featureFlagDefinitions.ts`.

یک فلگ boolean زمانی **فعال** در نظر گرفته میشود که مقدار مؤثر آن `"true"`،
`"1"` یا `"yes"` باشد (`isFeatureFlagEnabled()` را ببینید).

> [!NOTE]
> بیشتر فلگها همچنین یک متغیر محیطی متناظر با **همان نام** دارند
> که در [`ENVIRONMENT.md`](./ENVIRONMENT.md) مستند شده است. بازنویسی DB فلگ
> نسبت به آن متغیر محیطی اولویت دارد. فلگی با
> `requiresRestart: true` بلافاصله ذخیره میشود، اما فقط هنگام راهاندازی
> فرایند دوباره خوانده میشود — تغییر آن، بنر **«راهاندازی مجدد سرور»** را در داشبورد نمایش میدهد.

که وقتی نه بازنویسی DB و نه متغیر محیطی وجود داشته باشد، استفاده میشود.

| `PROXY_HEALTH_BLOCKED_RESETS_STREAK`      | boolean | `false` | در پیمایش سلامت پروکسی، کاوشی که هدف آن را رد کرده است (401/403/429)، زنجیره شکستهای متوالی پروکسی را بازنشانی میکند. بهطور پیشفرض غیرفعال است: یک رد درخواست خنثی باقی میماند (#10654). پاسخ 5xx در هر دو حالت نامشخص باقی میماند؛ رد درخواست هرگز پروکسی را حذف، غیرفعال یا دوباره فعال نمیکند. |
| `DB_HEALTHCHECK_STARTUP_DEFERRED_ENABLED` | boolean | `false` | بررسی یکپارچگی/سلامت DB هنگام راهاندازی را پس از آغاز پذیرش درخواستها توسط سرور (از طریق `setImmediate`) اجرا میکند، بهجای اینکه راهاندازی را تا تکمیل آن مسدود کند (#13717). بهطور پیشفرض غیرفعال است: راهاندازی دقیقاً مانند قبل از این PR مسدود میشود.                                         |

> [!NOTE]
> `INPUT_SANITIZER_BLOCK_THRESHOLD` و نام مستعار قدیمی آن
> `INJECTION_GUARD_BLOCK_THRESHOLD` حالت `block` مربوط به
> `INJECTION_GUARD_MODE` را تنظیم میکنند، اما متغیرهای محیطی سادهای هستند که توسط
> [`src/shared/utils/injectionSeverity.ts`](../../src/shared/utils/injectionSeverity.ts)
> خوانده میشوند، نه پرچمهای ویژگی: آنها نه بازنویسی DB دارند و نه کلید تغییر وضعیت در داشبورد. مراجعه کنید به
> [`ENVIRONMENT.md`](./ENVIRONMENT.md#4-security--authentication).

> [!NOTE]
> ستون `راهاندازی مجدد` پرچمهای دارای `requiresRestart: true` را مشخص میکند — مقدار
> فوراً ذخیره میشود، اما تنها پس از بارگذاری مجدد فرایند اعمال میشود. پرچمهای
> enum هر مقداری خارج از مجموعه مجاز خود را رد میکنند (اعتبارسنجی در سمت سرور هم در
> `setFeatureFlagOverride()` و هم در کنترلکننده REST `PUT` انجام میشود).

## تغییر وضعیت پرچمها

### داشبورد

به **داشبورد ← تنظیمات ← پرچمهای ویژگی**
(`/dashboard/settings/feature-flags`) بروید. شبکهٔ
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
از موارد زیر پشتیبانی میکند:

- **جستوجو** بر اساس کلید یا توضیحات و **فیلتر** بر اساس دستهبندی (بهعلاوهٔ نمای ساختگی
  **نیازمند راهاندازی مجدد**).
- یک **کلید تغییر وضعیت** برای پرچمهای بولی و یک **فهرست کشویی** برای پرچمهای enum
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- یک **نشان منبع** برای هر پرچم — `DB`، `ENV` یا `DEF` — که نشان میدهد مقدار
  مؤثر از کجا آمده است.
- یک دکمهٔ **بازنشانی** (که فقط برای پرچمهای دارای منبع `DB` نمایش داده میشود) برای حذف مقدار بازنویسیشده،
  و یک دکمهٔ **بازنشانی همهٔ مقادیر بازنویسیشده** در پایین صفحه.
- هنگام تغییر پرچمی با ویژگی `requiresRestart`، یک بنر **راهاندازی مجدد سرور** نمایش داده میشود.

### API مبتنی بر REST

همهٔ عملیات از طریق یک مسیر واحد انجام میشوند:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts).
هر متد به یک نشست احراز هویتشدهٔ داشبورد نیاز دارد (در غیر این صورت `401`).

#### `GET /api/settings/feature-flags`

همهٔ پرچمها را همراه با مقدار مؤثر، منبع و یک خلاصه برمیگرداند.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... همهٔ 72 پرچم
  ],
  "summary": {
    "total": 56,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

یک مقدار بازنویسیشده را برای یک پرچم تنظیم یا حذف میکند. بدنه: `{ key: string; value?: string }`.
حذف `value` از بدنه، مقدار بازنویسیشده را حذف میکند (و مقدار env / پیشفرض را بازمیگرداند).

```bash
# تنظیم یک مقدار بازنویسیشده در DB
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# حذف مقدار بازنویسیشده (بدون "value")
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

پاسخ، `effectiveValue`/`source` جدید، `previousValue`/
`previousSource` و `requiresRestart` را بازتاب میدهد. کلیدهای ناشناخته و مقادیر enum
خارج از محدوده با `400` رد میشوند.

#### `DELETE /api/settings/feature-flags`

**همهٔ** مقادیر بازنویسیشدهٔ DB را یکباره پاک میکند و هر پرچم را به مقدار env / پیشفرض آن
بازمیگرداند. `{ cleared: <count>, message: "..." }` را برمیگرداند.

> [!NOTE]
> پرچمهایی با `requiresRestart: true` فقط پس از بارگذاری مجدد فرایند اعمال میشوند.
> جریان راهاندازی مجدد داشبورد، `POST /api/restart` را فراخوانی میکند و سپس تا زمانی که
> سرور دوباره در دسترس قرار گیرد، `GET /api/health/ping` را بهطور دورهای بررسی میکند.

## مسیر جایگزین اضطراری بودجه

`OMNIROUTE_EMERGENCY_FALLBACK` (دستهبندی `runtime`، مقدار پیشفرض `true`) مسیر
جایگزین رایگان اضطراری را در
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts)
کنترل میکند. هنگامی که فعال باشد، درخواستهایی که بودجهٔ خود را تمام میکنند، بهجای شکست کامل
به یک ارائهدهنده/مدل جایگزین رایگان هدایت میشوند. برای غیرفعال کردن این رفتار و شکست خوردن درخواستهایی
که بودجهشان تمام شده است، آن را — از طریق کلید تغییر وضعیت داشبورد، یک مقدار بازنویسیشده در DB یا متغیر محیطی
`OMNIROUTE_EMERGENCY_FALLBACK` — روی `false` (یا `0`) تنظیم کنید.
(در PRهای #3741 / #3752 بهصورت یک کلید تغییر وضعیت در داشبورد ارائه شده است.)
