Dva způsoby, jak připojit Cursor za OmniRoute bez relace IDE:

1. **Poskytovatel `cursor-api`** (karta „Cursor API“, alias `cua`): poskytovatel
   využívající API klíč, který uchovává uživatelský API klíč Cursoru (`crsr_…`,
   vygenerovaný na `https://cursor.com/dashboard/api`). Libovolný klient
   OmniRoute pak přistupuje k modelům Cursoru prostřednictvím
   `/v1/chat/completions` jako `cursor-api/<model>` nebo `cua/<model>`, přičemž
   se uplatní obvyklé vrstvy pro kvóty, záložní mechanismy a protokolování.
   Poskytovatel IDE (`cursor`, relace OAuth/IDE) zůstává beze změny.
2. **Přímé předávání Cursor CLI**: nasměrujte Cursor CLI (`agent`) na OmniRoute,
   aby každé RPC volání provedené CLI bylo ověřeno pomocí API klíče OmniRoute,
   předáno Cursoru s přihlašovacími údaji připojení `cursor-api` a zaznamenáno
   na stránce Protokoly.

## Proč se klíč vyměňuje

`api2.cursor.sh` odmítá nezpracovaný klíč `crsr_…` jako token Bearer (401).
Cursor CLI nejprve odešle klíč metodou POST na `/auth/exchange_user_api_key`
a obdrží relační JWT, jehož platnost vyprší po jedné hodině; vrácený
`refreshToken` obsahuje stejnou hodnotu `exp`, takže obnovení znamená opětovnou
výměnu klíče.
`open-sse/services/cursorApiKeyAuth.ts` tuto výměnu provádí, ukládá do mezipaměti
jeden relační token pro každý klíč, znovu jej vymění pět minut před vypršením
platnosti a odstraní token z mezipaměti, když Cursor odpoví stavem 401.
`CursorExecutor` jej volá těsně před otevřením nadřazeného streamu pro připojení
`cursor-api`.

## Poskytovatel `cursor-api`

Registr: `open-sse/config/providers/registry/cursor/index.ts`
(`cursor_apiProvider`, `authType: "apikey"`, stejné hodnoty `format`, `baseUrl`
a `models` jako u `cursor`). Karta katalogu:
`src/shared/constants/providers/apikey/specialty-media.ts`. Mapa vykonavatelů:
`open-sse/executors/index.ts` (`"cursor-api"` / `cua` →
`new CursorExecutor("cursor-api")`).

Ovládací panel: Poskytovatelé → Cursor API → Přidat API klíč.

REST:

```bash
curl -sS -X POST http://localhost:20128/api/providers \
  -H "Content-Type: application/json" \
  -d '{"provider":"cursor-api","name":"cursor-api-key","apiKey":"crsr_…","priority":1}'
```

Poté:

```bash
curl -sS http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <omniroute-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"cursor-api/auto","messages":[{"role":"user","content":"say PONG"}]}'
```

Poznámky:

- Seznam modelů pro `cursor-api` pochází ze statického registru Cursoru
  (stejného seznamu, který poskytovatel IDE používá jako záložní); na hostiteli
  OmniRoute není nutné instalovat `cursor-agent`.
- `POST /api/providers/{id}/refresh-cursor` je určen pouze pro poskytovatele IDE
  `cursor`; připojení `cursor-api` nemají žádnou relaci IDE, kterou by bylo
  možné obnovit.

## Přímé předávání Cursor CLI

Trasa: `src/app/api/cursor-cli/[...path]/route.ts` →
`open-sse/handlers/cursorCliProxy.ts`. Prefix `/api/cursor-cli/` je zaregistrován
v `src/shared/constants/publicApiRoutes.ts`, protože obslužná rutina provádí
vlastní ověřování:

| Cesta                                                                                                                         | Ověření očekávané od CLI     | Co OmniRoute provede                                                                                                                                                         |
| ----------------------------------------------------------------------------------------------------------------------------- | ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /auth/exchange_user_api_key`                                                                                            | `Bearer <OmniRoute API key>` | Ověří klíč, vytvoří JWT HS256 s platností 1 hodinu (podepsané pomocí `JWT_SECRET`) a vrátí jej                                                                               |
| každá další cesta (`/aiserver.v1.*`, `/agent.v1.AgentService/RunSSE`, `/aiserver.v1.BidiService/BidiAppend`, `/v1/traces`, …) | `Bearer <that JWT>`          | Ověří vydavatele, cílovou skupinu a dobu platnosti, vybere aktivní připojení `cursor-api`, nahradí hlavičku Authorization vyměněným tokenem Cursoru a streamuje odpověď zpět |

CLI dekóduje `exp` z jakéhokoli přijatého tokenu, takže pokud mu předáte
neprůhledný token, provede opětovnou výměnu téměř před každým požadavkem;
vytvořený JWT tomu zabraňuje. Odpověď 401 od OmniRoute způsobí, že CLI provede
výměnu znovu.

### Nastavení

1. Vytvořte API klíč OmniRoute (Ovládací panel → API klíče) a připojení
   `cursor-api`.
2. Nastavte CLI tak, aby pro stream agenta používalo HTTP/1.1. V souboru
   `~/.cursor/cli-config.json`:

   ```json
   { "network": { "useHttp1ForAgent": true } }
   ```

   Bez tohoto nastavení CLI otevře interakci agenta přes HTTP/2 vůči samostatně
   nakonfigurovanému hostiteli agenta a přes koncový bod budou procházet pouze
   RPC volání řídicí vrstvy.

3. Spusťte CLI proti OmniRoute:

   ```bash
   export CURSOR_API_ENDPOINT=http://localhost:20128/api/cursor-cli
   export CURSOR_API_KEY=<omniroute-api-key>
   agent -p --trust "Reply with exactly OK"
   ```

Každý přenos se objeví v Protokolech s poskytovatelem `cursor-api`, typem
požadavku `cursor-cli` a cestou `/api/cursor-cli/<rpc>` a bude přiřazen
k API klíči OmniRoute a připojení, které jej obsloužilo.

### Režimy selhání

| Situace                                         | Odpověď pro CLI                                          |
| ----------------------------------------------- | -------------------------------------------------------- |
| Neznámý klíč OmniRoute a `REQUIRE_API_KEY=true` | 401 `unauthenticated` při výměně                         |
| `REQUIRE_API_KEY=false`                         | anonymní relace (odpovídá chování `/v1/*`)               |
| Expirovaný / cizí / pozměněný JWT relace        | 401, CLI provede výměnu znovu                            |
| Klíč API OmniRoute odvolaný po výměně           | 401 při následujícím RPC                                 |
| Žádné aktivní připojení `cursor-api`            | 503 `unavailable`                                        |
| Cursor odmítne klíč připojení                   | 401 `unauthenticated`, relace v mezipaměti je odstraněna |
| Nadřazená služba je nedostupná                  | 502 `unavailable` (sanitizovaná zpráva)                  |
| Proměnná `JWT_SECRET` není nastavena            | 503 při výměně                                           |
