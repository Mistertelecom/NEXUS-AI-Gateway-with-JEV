Két módon helyezhető a Cursor az OmniRoute mögé IDE-munkamenet nélkül:

1. **`cursor-api` szolgáltató** („Cursor API” kártya, alias: `cua`): API-kulcsos
   szolgáltató, amely egy Cursor felhasználói API-kulcsot tárol (`crsr_…`, amely a
   `https://cursor.com/dashboard/api` oldalon hozható létre). Ezután bármely
   OmniRoute-kliens elérheti a Cursor-modelleket a `/v1/chat/completions`
   végponton keresztül `cursor-api/<model>` vagy `cua/<model>` néven, a szokásos
   kvóta-, tartalékútvonal- és naplózási rétegekkel. Az IDE-szolgáltató
   (`cursor`, OAuth-/IDE-munkamenet) változatlan marad.
2. **Cursor CLI-átengedés**: irányítsa a Cursor CLI-t (`agent`) az OmniRoute-ra,
   így a CLI minden RPC-hívása egy OmniRoute API-kulccsal lesz hitelesítve,
   továbbításra kerül a Cursor felé egy `cursor-api` kapcsolat hitelesítő
   adatával, és rögzítésre kerül a Naplók oldalon.

## Miért történik kulcscsere

Az `api2.cursor.sh` elutasítja a nyers `crsr_…` kulcsot Bearer tokenként (401).
A Cursor CLI először POST-kéréssel elküldi a kulcsot az
`/auth/exchange_user_api_key` végpontra, és egy egy óra múlva lejáró munkamenet-
JWT-t kap; a visszaadott `refreshToken` ugyanazt az `exp` értéket tartalmazza,
ezért a frissítés a kulcs ismételt cseréjét jelenti.
Az `open-sse/services/cursorApiKeyAuth.ts` végrehajtja ezt a cserét, kulcsonként
egy munkamenettokent gyorsítótáraz, öt perccel a lejárat előtt ismét elvégzi a
cserét, és törli a gyorsítótárazott tokent, amikor a Cursor 401-es választ ad.
A `CursorExecutor` közvetlenül a felsőbb szintű adatfolyam megnyitása előtt
hívja meg ezt a `cursor-api` kapcsolatok esetében.

## A `cursor-api` szolgáltató

Regisztrációs adatbázis: `open-sse/config/providers/registry/cursor/index.ts`
(`cursor_apiProvider`, `authType: "apikey"`, ugyanaz a `format`, `baseUrl` és
`models`, mint a `cursor` esetében). Katalóguskártya:
`src/shared/constants/providers/apikey/specialty-media.ts`. Végrehajtó-leképezés:
`open-sse/executors/index.ts` (`"cursor-api"` / `cua` →
`new CursorExecutor("cursor-api")`).

Vezérlőpult: Szolgáltatók → Cursor API → API-kulcs hozzáadása.

REST:

```bash
curl -sS -X POST http://localhost:20128/api/providers \
  -H "Content-Type: application/json" \
  -d '{"provider":"cursor-api","name":"cursor-api-key","apiKey":"crsr_…","priority":1}'
```

Ezután:

```bash
curl -sS http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <omniroute-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"cursor-api/auto","messages":[{"role":"user","content":"say PONG"}]}'
```

Megjegyzések:

- A `cursor-api` modelllistája a statikus Cursor-regisztrációs adatbázisból
  származik (ugyanabból a listából, amelyet az IDE-szolgáltató tartalékként
  használ); nincs szükség a `cursor-agent` telepítésére az OmniRoute gazdagépén.
- A `POST /api/providers/{id}/refresh-cursor` kizárólag a `cursor`
  IDE-szolgáltatóhoz használható; a `cursor-api` kapcsolatok nem rendelkeznek
  megújítandó IDE-munkamenettel.

## Cursor CLI-átengedés

Útvonal: `src/app/api/cursor-cli/[...path]/route.ts` →
`open-sse/handlers/cursorCliProxy.ts`. Az `/api/cursor-cli/` előtag azért van
regisztrálva a `src/shared/constants/publicApiRoutes.ts` fájlban, mert a kezelő
saját maga végzi a hitelesítést:

| Útvonal                                                                                                                          | A CLI-től elvárt hitelesítés | Az OmniRoute művelete                                                                                                                                                                                |
| -------------------------------------------------------------------------------------------------------------------------------- | ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /auth/exchange_user_api_key`                                                                                               | `Bearer <OmniRoute API key>` | Ellenőrzi a kulcsot, létrehoz egy 1 órás HS256 JWT-t (a `JWT_SECRET` használatával aláírva), majd visszaadja azt                                                                                     |
| minden egyéb útvonal (`/aiserver.v1.*`, `/agent.v1.AgentService/RunSSE`, `/aiserver.v1.BidiService/BidiAppend`, `/v1/traces`, …) | `Bearer <that JWT>`          | Ellenőrzi a kibocsátót, a célközönséget és a lejáratot, kiválaszt egy aktív `cursor-api` kapcsolatot, lecseréli az Authorization fejlécet a kicserélt Cursor-tokenre, majd visszaközvetíti a választ |

A CLI dekódolja az `exp` értéket a kapott tokenből, ezért egy átlátszatlan token
átadása esetén szinte minden kérés előtt újból elvégezné a cserét; a létrehozott
JWT ezt elkerüli. Az OmniRoute-tól kapott 401-es válasz hatására a CLI ismét
elvégzi a cserét.

### Beállítás

1. Hozzon létre egy OmniRoute API-kulcsot (Vezérlőpult → API-kulcsok) és egy
   `cursor-api` kapcsolatot.
2. Állítsa be a CLI-t úgy, hogy HTTP/1.1-et használjon az ügynök adatfolyamához.
   A `~/.cursor/cli-config.json` fájlban:

   ```json
   { "network": { "useHttp1ForAgent": true } }
   ```

   Enélkül a CLI HTTP/2-n keresztül nyitja meg az ügynökfordulót egy külön
   konfigurált ügynökgazdagép felé, és csak a vezérlősík RPC-hívásai haladnak át
   a végponton.

3. Futtassa a CLI-t az OmniRoute használatával:

   ```bash
   export CURSOR_API_ENDPOINT=http://localhost:20128/api/cursor-cli
   export CURSOR_API_KEY=<omniroute-api-key>
   agent -p --trust "Reply with exactly OK"
   ```

Minden továbbítás bekerül a Naplókba `cursor-api` szolgáltatóval,
`cursor-cli` kéréstípussal és `/api/cursor-cli/<rpc>` útvonallal, az OmniRoute
API-kulcshoz és a kérést kiszolgáló kapcsolathoz rendelve.

### Hibalehetőségek

| Helyzet                                              | Válasz a CLI-nak                                              |
| ---------------------------------------------------- | ------------------------------------------------------------- |
| Ismeretlen OmniRoute-kulcs és `REQUIRE_API_KEY=true` | 401 `unauthenticated` a cserénél                              |
| `REQUIRE_API_KEY=false`                              | névtelen munkamenet (a `/v1/*` viselkedését követi)           |
| Lejárt / idegen / módosított munkamenet-JWT          | 401, a CLI újra végrehajtja a cserét                          |
| A csere után visszavont OmniRoute API-kulcs          | 401 a következő RPC-nél                                       |
| Nincs aktív `cursor-api`-kapcsolat                   | 503 `unavailable`                                             |
| A Cursor elutasítja a kapcsolat kulcsát              | 401 `unauthenticated`, a gyorsítótárazott munkamenet törlődik |
| A felsőbb szintű szolgáltatás nem érhető el          | 502 `unavailable` (megtisztított üzenet)                      |
| A `JWT_SECRET` nincs beállítva                       | 503 a cserénél                                                |
