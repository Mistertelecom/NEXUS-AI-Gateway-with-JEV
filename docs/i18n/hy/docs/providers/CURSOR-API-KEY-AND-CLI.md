Cursor-ը OmniRoute-ի հետևում առանց IDE աշխատաշրջանի տեղադրելու երկու եղանակ կա.

1. **`cursor-api` մատակարար** (`Cursor API` քարտ, `cua` կեղծանուն). API բանալիով
   մատակարար, որը պահում է Cursor-ի օգտատիրոջ API բանալին (`crsr_…`, ստեղծվում է
   `https://cursor.com/dashboard/api` հասցեում)։ Այնուհետև OmniRoute-ի ցանկացած հաճախորդ
   կարող է դիմել Cursor-ի մոդելներին `/v1/chat/completions`-ի միջոցով՝ որպես
   `cursor-api/<model>` կամ `cua/<model>`՝ քվոտայի, պահուստային տարբերակի և գրանցամատյանի
   սովորական շերտերով։ IDE մատակարարը (`cursor`, OAuth/IDE աշխատաշրջան) մնում է անփոփոխ։
2. **Cursor CLI-ի թափանցիկ փոխանցում**. Cursor CLI-ն (`agent`) ուղղեք դեպի OmniRoute, որպեսզի
   CLI-ի կատարած յուրաքանչյուր RPC վավերացվի OmniRoute API բանալիով, փոխանցվի
   Cursor-ին՝ օգտագործելով `cursor-api` կապի հավատարմագրերը, և գրանցվի
   Logs էջում։

## Ինչու է բանալին փոխանակվում

`api2.cursor.sh`-ը մերժում է չմշակված `crsr_…` բանալին՝ որպես Bearer թոքեն (401)։ Cursor
CLI-ն սկզբում POST հարցմամբ բանալին ուղարկում է `/auth/exchange_user_api_key` և ստանում է
աշխատաշրջանի JWT, որի ժամկետը լրանում է մեկ ժամ անց։ Վերադարձված `refreshToken`-ն ունի նույն
`exp`-ը, ուստի թարմացումը նշանակում է բանալու կրկնակի փոխանակում։
`open-sse/services/cursorApiKeyAuth.ts`-ը կատարում է այդ փոխանակումը, յուրաքանչյուր բանալու
համար պահում է մեկ աշխատաշրջանի թոքեն, կրկին փոխանակում է այն ժամկետի ավարտից հինգ րոպե առաջ
և հեռացնում է քեշավորված թոքենը, երբ Cursor-ը պատասխանում է 401 կարգավիճակով։ `CursorExecutor`-ը
կանչում է այն անմիջապես `cursor-api` կապերի համար վերին հոսքի բացումից առաջ։

## `cursor-api` մատակարարը

Գրանցամատյան՝ `open-sse/config/providers/registry/cursor/index.ts`
(`cursor_apiProvider`, `authType: "apikey"`, նույն `format`-ը, `baseUrl`-ը և
`models`-ը, ինչ `cursor`-ինը)։ Կատալոգի քարտ՝
`src/shared/constants/providers/apikey/specialty-media.ts`։ Կատարիչների քարտեզ՝
`open-sse/executors/index.ts` (`"cursor-api"` / `cua` →
`new CursorExecutor("cursor-api")`)։

Կառավարման վահանակ՝ Providers → Cursor API → Add API key։

REST.

```bash
curl -sS -X POST http://localhost:20128/api/providers \
  -H "Content-Type: application/json" \
  -d '{"provider":"cursor-api","name":"cursor-api-key","apiKey":"crsr_…","priority":1}'
```

Այնուհետև՝

```bash
curl -sS http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <omniroute-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"cursor-api/auto","messages":[{"role":"user","content":"say PONG"}]}'
```

Նշումներ.

- `cursor-api`-ի մոդելների ցանկը վերցվում է Cursor-ի ստատիկ գրանցամատյանից (նույն
  ցանկը, որին որպես պահուստային տարբերակ անցնում է IDE մատակարարը)։ OmniRoute հոսթում
  `cursor-agent`-ի տեղադրում չի պահանջվում։
- `POST /api/providers/{id}/refresh-cursor`-ը նախատեսված է միայն `cursor` IDE մատակարարի
  համար։ `cursor-api` կապերը չունեն թարմացման ենթակա IDE աշխատաշրջան։

## Cursor CLI-ի թափանցիկ փոխանցում

Երթուղի՝ `src/app/api/cursor-cli/[...path]/route.ts` →
`open-sse/handlers/cursorCliProxy.ts`։ `/api/cursor-cli/` նախածանցը
գրանցված է `src/shared/constants/publicApiRoutes.ts`-ում, քանի որ մշակիչը
կիրառում է իր սեփական վավերացումը.

| Ուղի                                                                                                                               | CLI-ից ակնկալվող վավերացում  | Ինչ է անում OmniRoute-ը                                                                                                                                                                      |
| ---------------------------------------------------------------------------------------------------------------------------------- | ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /auth/exchange_user_api_key`                                                                                                 | `Bearer <OmniRoute API key>` | Վավերացնում է բանալին, ստեղծում է 1 ժամ գործողությամբ HS256 JWT (`JWT_SECRET`-ով ստորագրված) և վերադարձնում այն                                                                              |
| յուրաքանչյուր այլ ուղի (`/aiserver.v1.*`, `/agent.v1.AgentService/RunSSE`, `/aiserver.v1.BidiService/BidiAppend`, `/v1/traces`, …) | `Bearer <that JWT>`          | Ստուգում է թողարկողին/լսարանին/ժամկետի ավարտը, ընտրում է ակտիվ `cursor-api` կապ, Authorization վերնագիրը փոխարինում է փոխանակված Cursor թոքենով և պատասխանը հոսքային եղանակով վերադարձնում է |

CLI-ն վերծանում է `exp`-ը ստացված ցանկացած թոքենից, ուստի անթափանց
թոքեն տրամադրելու դեպքում այն կրկնակի փոխանակում է կատարում գրեթե յուրաքանչյուր հարցումից առաջ։
Ստեղծված JWT-ն խուսափում է դրանից։ OmniRoute-ից ստացված 401 պատասխանը ստիպում է CLI-ին
կրկին կատարել փոխանակումը։

### Կարգավորում

1. Ստեղծեք OmniRoute API բանալի (Dashboard → API keys) և `cursor-api`
   կապ։
2. CLI-ին հրահանգեք գործակալի հոսքի համար օգտագործել HTTP/1.1։
   `~/.cursor/cli-config.json`-ում՝

   ```json
   { "network": { "useHttp1ForAgent": true } }
   ```

   Առանց դրա CLI-ն գործակալի քայլը բացում է HTTP/2-ով՝ առանձին
   կազմաձևված գործակալի հոսթի նկատմամբ, և վերջնակետով անցնում են միայն
   կառավարման հարթակի RPC-ները։

3. Գործարկեք CLI-ն OmniRoute-ի նկատմամբ՝

   ```bash
   export CURSOR_API_ENDPOINT=http://localhost:20128/api/cursor-cli
   export CURSOR_API_KEY=<omniroute-api-key>
   agent -p --trust "Reply with exactly OK"
   ```

Յուրաքանչյուր անցում հայտնվում է Logs-ում՝ որպես `cursor-api` մատակարար, `cursor-cli`
հարցման տեսակ և `/api/cursor-cli/<rpc>` ուղի՝ վերագրված OmniRoute API բանալուն և այն
սպասարկած կապին։

### Խափանման տարբերակներ

| Իրավիճակ                                         | Պատասխան CLI-ին                                      |
| ------------------------------------------------ | ---------------------------------------------------- |
| Անհայտ OmniRoute բանալի և `REQUIRE_API_KEY=true` | 401 `unauthenticated`՝ փոխանակման ժամանակ            |
| `REQUIRE_API_KEY=false`                          | անանուն սեսիա (համապատասխանում է `/v1/*` վարքագծին)  |
| Ժամկետանց / օտար / կեղծված սեսիայի JWT           | 401, CLI-ն կրկին կատարում է փոխանակումը              |
| Փոխանակումից հետո չեղարկված OmniRoute API բանալի | 401՝ հաջորդ RPC-ի ժամանակ                            |
| Ակտիվ `cursor-api` կապ չկա                       | 503 `unavailable`                                    |
| Cursor-ը մերժում է կապի բանալին                  | 401 `unauthenticated`, քեշավորված սեսիան հեռացվում է |
| Վերին հոսքն անհասանելի է                         | 502 `unavailable` (մաքրված հաղորդագրություն)         |
| `JWT_SECRET`-ը սահմանված չէ                      | 503՝ փոխանակման ժամանակ                              |
