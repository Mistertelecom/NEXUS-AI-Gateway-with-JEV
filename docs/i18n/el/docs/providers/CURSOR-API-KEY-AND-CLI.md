Δύο τρόποι για να τοποθετήσετε το Cursor πίσω από το OmniRoute χωρίς συνεδρία IDE:

1. **Πάροχος `cursor-api`** (κάρτα "Cursor API", ψευδώνυμο `cua`): ένας πάροχος
   με κλειδί API που διατηρεί ένα κλειδί API χρήστη του Cursor (`crsr_…`, το οποίο δημιουργείται στη διεύθυνση
   `https://cursor.com/dashboard/api`). Στη συνέχεια, οποιοσδήποτε πελάτης OmniRoute αποκτά πρόσβαση
   στα μοντέλα Cursor μέσω του `/v1/chat/completions` ως `cursor-api/<model>` ή
   `cua/<model>`, με τα συνήθη επίπεδα ορίων χρήσης, εναλλακτικής δρομολόγησης και καταγραφής. Ο πάροχος IDE
   (`cursor`, συνεδρία OAuth/IDE) παραμένει αμετάβλητος.
2. **Άμεση προώθηση του Cursor CLI**: κατευθύνετε το Cursor CLI (`agent`) προς το OmniRoute, ώστε
   κάθε RPC που πραγματοποιεί το CLI να πιστοποιείται με ένα κλειδί API του OmniRoute, να προωθείται
   στο Cursor με τα διαπιστευτήρια μιας σύνδεσης `cursor-api` και να καταγράφεται στη
   σελίδα Logs.

## Γιατί γίνεται ανταλλαγή του κλειδιού

Το `api2.cursor.sh` απορρίπτει ένα ακατέργαστο κλειδί `crsr_…` ως διακριτικό Bearer (401). Το Cursor
CLI αρχικά στέλνει το κλειδί μέσω POST στο `/auth/exchange_user_api_key` και λαμβάνει ένα JWT
συνεδρίας που λήγει μετά από μία ώρα· το επιστρεφόμενο `refreshToken` έχει την ίδια
τιμή `exp`, επομένως η ανανέωση απαιτεί εκ νέου ανταλλαγή του κλειδιού.
Το `open-sse/services/cursorApiKeyAuth.ts` πραγματοποιεί αυτή την ανταλλαγή, αποθηκεύει προσωρινά ένα διακριτικό
συνεδρίας ανά κλειδί, πραγματοποιεί εκ νέου την ανταλλαγή πέντε λεπτά πριν από τη λήξη και διαγράφει το προσωρινά αποθηκευμένο
διακριτικό όταν το Cursor απαντήσει με 401. Το `CursorExecutor` το καλεί ακριβώς πριν ανοίξει
τη ροή προς την υπηρεσία προέλευσης για συνδέσεις `cursor-api`.

## Ο πάροχος `cursor-api`

Μητρώο: `open-sse/config/providers/registry/cursor/index.ts`
(`cursor_apiProvider`, `authType: "apikey"`, ίδια `format`, `baseUrl` και
`models` με το `cursor`). Κάρτα καταλόγου:
`src/shared/constants/providers/apikey/specialty-media.ts`. Αντιστοίχιση εκτελεστών:
`open-sse/executors/index.ts` (`"cursor-api"` / `cua` →
`new CursorExecutor("cursor-api")`).

Πίνακας ελέγχου: Providers → Cursor API → Add API key.

REST:

```bash
curl -sS -X POST http://localhost:20128/api/providers \
  -H "Content-Type: application/json" \
  -d '{"provider":"cursor-api","name":"cursor-api-key","apiKey":"crsr_…","priority":1}'
```

Στη συνέχεια:

```bash
curl -sS http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <omniroute-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"cursor-api/auto","messages":[{"role":"user","content":"say PONG"}]}'
```

Σημειώσεις:

- Η λίστα μοντέλων για το `cursor-api` προέρχεται από το στατικό μητρώο του Cursor (την
  ίδια λίστα στην οποία καταφεύγει ο πάροχος IDE)· δεν απαιτείται εγκατάσταση του `cursor-agent`
  στον κεντρικό υπολογιστή του OmniRoute.
- Το `POST /api/providers/{id}/refresh-cursor` προορίζεται μόνο για τον πάροχο IDE `cursor`·
  οι συνδέσεις `cursor-api` δεν διαθέτουν συνεδρία IDE προς ανανέωση.

## Άμεση προώθηση του Cursor CLI

Διαδρομή: `src/app/api/cursor-cli/[...path]/route.ts` →
`open-sse/handlers/cursorCliProxy.ts`. Το πρόθεμα `/api/cursor-cli/` είναι
καταχωρισμένο στο `src/shared/constants/publicApiRoutes.ts`, επειδή ο χειριστής
επιβάλλει τον δικό του έλεγχο ταυτότητας:

| Διαδρομή                                                                                                                       | Αναμενόμενος έλεγχος ταυτότητας από το CLI | Τι κάνει το OmniRoute                                                                                                                                                                                 |
| ------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /auth/exchange_user_api_key`                                                                                             | `Bearer <OmniRoute API key>`               | Επικυρώνει το κλειδί, δημιουργεί ένα JWT HS256 διάρκειας 1 ώρας (υπογεγραμμένο με `JWT_SECRET`) και το επιστρέφει                                                                                     |
| κάθε άλλη διαδρομή (`/aiserver.v1.*`, `/agent.v1.AgentService/RunSSE`, `/aiserver.v1.BidiService/BidiAppend`, `/v1/traces`, …) | `Bearer <that JWT>`                        | Επαληθεύει εκδότη/κοινό/λήξη, επιλέγει μια ενεργή σύνδεση `cursor-api`, αντικαθιστά την κεφαλίδα Authorization με το διακριτικό Cursor που προέκυψε από την ανταλλαγή και μεταδίδει την απάντηση πίσω |

Το CLI αποκωδικοποιεί το `exp` από οποιοδήποτε διακριτικό λαμβάνει, επομένως η παροχή ενός αδιαφανούς
διακριτικού το αναγκάζει να πραγματοποιεί εκ νέου την ανταλλαγή πριν από σχεδόν κάθε αίτημα· το JWT που δημιουργείται αποφεύγει
αυτό το πρόβλημα. Μια απόκριση 401 από το OmniRoute αναγκάζει το CLI να πραγματοποιήσει ξανά την ανταλλαγή.

### Ρύθμιση

1. Δημιουργήστε ένα κλειδί API του OmniRoute (Dashboard → API keys) και μια σύνδεση
   `cursor-api`.
2. Ρυθμίστε το CLI ώστε να χρησιμοποιεί HTTP/1.1 για τη ροή του agent. Στο
   `~/.cursor/cli-config.json`:

   ```json
   { "network": { "useHttp1ForAgent": true } }
   ```

   Χωρίς αυτή τη ρύθμιση, το CLI ανοίγει τον κύκλο αλληλεπίδρασης του agent μέσω HTTP/2 προς έναν ξεχωριστά
   διαμορφωμένο κεντρικό υπολογιστή agent και μόνο τα RPC του επιπέδου ελέγχου περνούν μέσω του
   τελικού σημείου.

3. Εκτελέστε το CLI μέσω του OmniRoute:

   ```bash
   export CURSOR_API_ENDPOINT=http://localhost:20128/api/cursor-cli
   export CURSOR_API_KEY=<omniroute-api-key>
   agent -p --trust "Reply with exactly OK"
   ```

Κάθε βήμα καταγράφεται στο Logs με πάροχο `cursor-api`, τύπο αιτήματος `cursor-cli`,
διαδρομή `/api/cursor-cli/<rpc>`, και αποδίδεται στο κλειδί API του OmniRoute και στη
σύνδεση που το εξυπηρέτησε.

### Τρόποι αποτυχίας

| Κατάσταση                                                 | Απόκριση στο CLI                                              |
| --------------------------------------------------------- | ------------------------------------------------------------- |
| Άγνωστο κλειδί OmniRoute και `REQUIRE_API_KEY=true`       | 401 `unauthenticated` κατά την ανταλλαγή                      |
| `REQUIRE_API_KEY=false`                                   | ανώνυμη συνεδρία (αντικατοπτρίζει τη συμπεριφορά του `/v1/*`) |
| Ληγμένο / ξένο / παραποιημένο JWT συνεδρίας               | 401, το CLI εκτελεί ξανά την ανταλλαγή                        |
| Το κλειδί API του OmniRoute ανακλήθηκε μετά την ανταλλαγή | 401 στο επόμενο RPC                                           |
| Καμία ενεργή σύνδεση `cursor-api`                         | 503 `unavailable`                                             |
| Το Cursor απορρίπτει το κλειδί της σύνδεσης               | 401 `unauthenticated`, η αποθηκευμένη συνεδρία διαγράφεται    |
| Η upstream υπηρεσία δεν είναι προσβάσιμη                  | 502 `unavailable` (εξυγιασμένο μήνυμα)                        |
| Το `JWT_SECRET` δεν έχει οριστεί                          | 503 κατά την ανταλλαγή                                        |
