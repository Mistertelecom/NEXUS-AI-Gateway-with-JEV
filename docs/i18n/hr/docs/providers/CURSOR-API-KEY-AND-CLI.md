Dva načina za postavljanje Cursora iza OmniRoutea bez IDE sesije:

1. **Pružatelj `cursor-api`** (kartica „Cursor API”, pseudonim `cua`): pružatelj s
   API ključem koji čuva korisnički API ključ Cursora (`crsr_…`, generiran na
   `https://cursor.com/dashboard/api`). Svaki OmniRoute klijent zatim pristupa
   Cursor modelima putem `/v1/chat/completions` kao `cursor-api/<model>` ili
   `cua/<model>`, uz uobičajene slojeve kvota, pričuvnog usmjeravanja i
   zapisivanja. IDE pružatelj (`cursor`, OAuth/IDE sesija) ostaje nepromijenjen.
2. **Izravno prosljeđivanje Cursor CLI-ja**: usmjerite Cursor CLI (`agent`) na
   OmniRoute kako bi svaki RPC koji CLI šalje bio autentificiran OmniRoute API
   ključem, proslijeđen Cursoru s vjerodajnicom veze `cursor-api` i zabilježen
   na stranici Zapisi.

## Zašto se ključ razmjenjuje

`api2.cursor.sh` odbija neobrađeni ključ `crsr_…` kao Bearer token (401). Cursor
CLI najprije šalje ključ metodom POST na `/auth/exchange_user_api_key` i prima
JWT sesije koji istječe nakon jednog sata; vraćeni `refreshToken` ima isti
`exp`, pa osvježavanje znači ponovnu razmjenu ključa.
`open-sse/services/cursorApiKeyAuth.ts` obavlja tu razmjenu, predmemorira jedan
token sesije po ključu, ponovno ga razmjenjuje pet minuta prije isteka i uklanja
predmemorirani token kada Cursor odgovori statusom 401. `CursorExecutor` ga
poziva neposredno prije otvaranja uzvodnog toka za veze `cursor-api`.

## Pružatelj `cursor-api`

Registar: `open-sse/config/providers/registry/cursor/index.ts`
(`cursor_apiProvider`, `authType: "apikey"`, isti `format`, `baseUrl` i
`models` kao `cursor`). Kartica kataloga:
`src/shared/constants/providers/apikey/specialty-media.ts`. Mapa izvršitelja:
`open-sse/executors/index.ts` (`"cursor-api"` / `cua` →
`new CursorExecutor("cursor-api")`).

Nadzorna ploča: Pružatelji → Cursor API → Dodaj API ključ.

REST:

```bash
curl -sS -X POST http://localhost:20128/api/providers \
  -H "Content-Type: application/json" \
  -d '{"provider":"cursor-api","name":"cursor-api-key","apiKey":"crsr_…","priority":1}'
```

Zatim:

```bash
curl -sS http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <omniroute-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"cursor-api/auto","messages":[{"role":"user","content":"say PONG"}]}'
```

Napomene:

- Popis modela za `cursor-api` dolazi iz statičkog registra Cursora (istog
  popisa koji IDE pružatelj koristi kao rezervnu opciju); instalacija paketa
  `cursor-agent` nije potrebna na OmniRoute hostu.
- `POST /api/providers/{id}/refresh-cursor` namijenjen je samo IDE pružatelju
  `cursor`; veze `cursor-api` nemaju IDE sesiju koju treba obnoviti.

## Izravno prosljeđivanje Cursor CLI-ja

Ruta: `src/app/api/cursor-cli/[...path]/route.ts` →
`open-sse/handlers/cursorCliProxy.ts`. Prefiks `/api/cursor-cli/` registriran je
u `src/shared/constants/publicApiRoutes.ts` jer obrađivač provodi vlastitu
autentifikaciju:

| Putanja                                                                                                                         | Autentifikacija koju CLI očekuje | Što OmniRoute radi                                                                                                                                                      |
| ------------------------------------------------------------------------------------------------------------------------------- | -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /auth/exchange_user_api_key`                                                                                              | `Bearer <OmniRoute API key>`     | Provjerava ključ, izdaje 1-satni HS256 JWT (potpisan s `JWT_SECRET`) i vraća ga                                                                                         |
| svaka druga putanja (`/aiserver.v1.*`, `/agent.v1.AgentService/RunSSE`, `/aiserver.v1.BidiService/BidiAppend`, `/v1/traces`, …) | `Bearer <that JWT>`              | Provjerava izdavatelja/publiku/istek, odabire aktivnu vezu `cursor-api`, zamjenjuje zaglavlje Authorization razmijenjenim Cursor tokenom i šalje odgovor natrag kao tok |

CLI dekodira `exp` iz bilo kojeg tokena koji primi, pa mu predaja neprozirnog
tokena uzrokuje ponovnu razmjenu prije gotovo svakog zahtjeva; izdani JWT to
izbjegava. Odgovor 401 iz OmniRoutea uzrokuje da CLI ponovno izvrši razmjenu.

### Postavljanje

1. Izradite OmniRoute API ključ (Nadzorna ploča → API ključevi) i vezu
   `cursor-api`.
2. Naložite CLI-ju da za tok agenta koristi HTTP/1.1. U datoteci
   `~/.cursor/cli-config.json`:

   ```json
   { "network": { "useHttp1ForAgent": true } }
   ```

   Bez toga CLI otvara interakciju agenta putem HTTP/2 prema zasebno
   konfiguriranom hostu agenta, a samo RPC-ovi kontrolne ravnine prolaze kroz
   krajnju točku.

3. Pokrenite CLI prema OmniRouteu:

   ```bash
   export CURSOR_API_ENDPOINT=http://localhost:20128/api/cursor-cli
   export CURSOR_API_KEY=<omniroute-api-key>
   agent -p --trust "Reply with exactly OK"
   ```

Svaki korak završava u Zapisima s pružateljem `cursor-api`, vrstom zahtjeva
`cursor-cli` i putanjom `/api/cursor-cli/<rpc>`, pripisan OmniRoute API ključu i
vezi koja ga je obradila.

### Načini neuspjeha

| Situacija                                         | Odgovor CLI-ju                                        |
| ------------------------------------------------- | ----------------------------------------------------- |
| Nepoznat OmniRoute ključ i `REQUIRE_API_KEY=true` | 401 `unauthenticated` pri razmjeni                    |
| `REQUIRE_API_KEY=false`                           | anonimna sesija (odražava ponašanje `/v1/*`)          |
| Istekao / strani / izmijenjen JWT sesije          | 401, CLI ponovno obavlja razmjenu                     |
| OmniRoute API ključ opozvan nakon razmjene        | 401 pri sljedećem RPC-u                               |
| Nema aktivne veze s `cursor-api`                  | 503 `unavailable`                                     |
| Cursor odbija ključ veze                          | 401 `unauthenticated`, predmemorirana sesija se briše |
| Uzvodna usluga nedostupna                         | 502 `unavailable` (sanitizirana poruka)               |
| `JWT_SECRET` nije postavljen                      | 503 pri razmjeni                                      |
