Cursor-u IDE sessiyası olmadan OmniRoute-un arxasında yerləşdirməyin iki yolu:

1. **`cursor-api` provayderi** (“Cursor API” kartı, ləqəb `cua`): Cursor istifadəçi API açarını (`crsr_…`, `https://cursor.com/dashboard/api` ünvanında yaradılır) saxlayan API açarı əsaslı provayder. Bundan sonra istənilən OmniRoute klienti adi kvota, ehtiyat keçid və jurnallaşdırma qatları ilə `/v1/chat/completions` vasitəsilə Cursor modellərinə `cursor-api/<model>` və ya `cua/<model>` kimi müraciət edə bilər. IDE provayderi (`cursor`, OAuth/IDE sessiyası) dəyişməz qalır.
2. **Cursor CLI birbaşa ötürməsi**: Cursor CLI-ni (`agent`) OmniRoute-a yönəldin ki, CLI-nin etdiyi hər RPC OmniRoute API açarı ilə autentifikasiya edilsin, `cursor-api` bağlantısının giriş məlumatları ilə Cursor-a ötürülsün və Logs səhifəsində qeydə alınsın.

## Açar niyə dəyişdirilir

`api2.cursor.sh` xam `crsr_…` açarını Bearer tokeni kimi qəbul etmir (401). Cursor CLI əvvəlcə açarı `/auth/exchange_user_api_key` ünvanına POST sorğusu ilə göndərir və bir saatdan sonra müddəti bitən sessiya JWT-si alır; qaytarılan `refreshToken` eyni `exp` dəyərini daşıyır, buna görə yeniləmə açarın yenidən dəyişdirilməsi deməkdir.
`open-sse/services/cursorApiKeyAuth.ts` bu dəyişdirməni həyata keçirir, hər açar üçün bir sessiya tokenini keşləyir, müddətin bitməsinə beş dəqiqə qalmış açarı yenidən dəyişdirir və Cursor 401 cavabı verdikdə keşlənmiş tokeni silir. `CursorExecutor` `cursor-api` bağlantıları üçün yuxarı axın yayımını açmazdan dərhal əvvəl onu çağırır.

## `cursor-api` provayderi

Reyestr: `open-sse/config/providers/registry/cursor/index.ts`
(`cursor_apiProvider`, `authType: "apikey"`, `cursor` ilə eyni `format`, `baseUrl` və
`models`). Kataloq kartı:
`src/shared/constants/providers/apikey/specialty-media.ts`. İcraçı xəritəsi:
`open-sse/executors/index.ts` (`"cursor-api"` / `cua` →
`new CursorExecutor("cursor-api")`).

İdarəetmə paneli: Providers → Cursor API → Add API key.

REST:

```bash
curl -sS -X POST http://localhost:20128/api/providers \
  -H "Content-Type: application/json" \
  -d '{"provider":"cursor-api","name":"cursor-api-key","apiKey":"crsr_…","priority":1}'
```

Sonra:

```bash
curl -sS http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <omniroute-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"cursor-api/auto","messages":[{"role":"user","content":"say PONG"}]}'
```

Qeydlər:

- `cursor-api` üçün modellərin siyahısı statik Cursor reyestrindən gəlir (IDE provayderinin ehtiyat olaraq istifadə etdiyi eyni siyahı); OmniRoute hostunda `cursor-agent` quraşdırılmasına ehtiyac yoxdur.
- `POST /api/providers/{id}/refresh-cursor` yalnız `cursor` IDE provayderi üçündür; `cursor-api` bağlantılarında yenilənəcək IDE sessiyası yoxdur.

## Cursor CLI birbaşa ötürməsi

Marşrut: `src/app/api/cursor-cli/[...path]/route.ts` →
`open-sse/handlers/cursorCliProxy.ts`. `/api/cursor-cli/` prefiksi
`src/shared/constants/publicApiRoutes.ts` faylında qeydiyyatdan keçirilib, çünki işləyici öz autentifikasiyasını tətbiq edir:

| Yol                                                                                                                            | CLI-dən gözlənilən autentifikasiya | OmniRoute-un etdiyi                                                                                                                                                                |
| ------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /auth/exchange_user_api_key`                                                                                             | `Bearer <OmniRoute API key>`       | Açarı doğrulayır, 1 saatlıq HS256 JWT (`JWT_SECRET` ilə imzalanır) yaradır və onu qaytarır                                                                                         |
| bütün digər yollar (`/aiserver.v1.*`, `/agent.v1.AgentService/RunSSE`, `/aiserver.v1.BidiService/BidiAppend`, `/v1/traces`, …) | `Bearer <that JWT>`                | Emitenti/auditoriyanı/bitmə müddətini doğrulayır, aktiv `cursor-api` bağlantısı seçir, Authorization başlığını dəyişdirilmiş Cursor tokeni ilə əvəz edir və cavabı geri yayımlayır |

CLI aldığı istənilən tokendən `exp` dəyərini dekodlaşdırır, buna görə ona qeyri-şəffaf token verilməsi demək olar ki, hər sorğudan əvvəl yenidən dəyişdirmə aparmasına səbəb olur; yaradılmış JWT bunun qarşısını alır. OmniRoute-dan gələn 401 cavabı CLI-nin dəyişdirməni yenidən həyata keçirməsinə səbəb olur.

### Quraşdırma

1. OmniRoute API açarı (Dashboard → API keys) və `cursor-api` bağlantısı yaradın.
2. CLI-yə agent yayımı üçün HTTP/1.1 istifadə etməsini bildirin.
   `~/.cursor/cli-config.json` faylında:

   ```json
   { "network": { "useHttp1ForAgent": true } }
   ```

   Bu parametr olmadan CLI agent sorğusunu ayrıca konfiqurasiya edilmiş agent hostuna HTTP/2 üzərindən açır və endpoint vasitəsilə yalnız idarəetmə müstəvisi RPC-ləri keçir.

3. CLI-ni OmniRoute-a qarşı işə salın:

   ```bash
   export CURSOR_API_ENDPOINT=http://localhost:20128/api/cursor-cli
   export CURSOR_API_KEY=<omniroute-api-key>
   agent -p --trust "Reply with exactly OK"
   ```

Hər keçid Logs bölməsinə `cursor-api` provayderi, `cursor-cli` sorğu növü və `/api/cursor-cli/<rpc>` yolu ilə düşür və OmniRoute API açarı ilə ona xidmət göstərən bağlantıya aid edilir.

### Xəta halları

| Vəziyyət                                            | CLI-a cavab                                      |
| --------------------------------------------------- | ------------------------------------------------ |
| Naməlum OmniRoute açarı və `REQUIRE_API_KEY=true`   | Mübadilə zamanı 401 `unauthenticated`            |
| `REQUIRE_API_KEY=false`                             | Anonim sessiya (`/v1/*` davranışını təkrarlayır) |
| Müddəti bitmiş / yad / dəyişdirilmiş sessiya JWT-si | 401, CLI yenidən mübadilə edir                   |
| Mübadilədən sonra OmniRoute API açarı ləğv edilib   | Növbəti RPC zamanı 401                           |
| Aktiv `cursor-api` bağlantısı yoxdur                | 503 `unavailable`                                |
| Cursor bağlantı açarını rədd edir                   | 401 `unauthenticated`, keşlənmiş sessiya silinir |
| Yuxarı axın əlçatmazdır                             | 502 `unavailable` (təmizlənmiş mesaj)            |
| `JWT_SECRET` təyin edilməyib                        | Mübadilə zamanı 503                              |
