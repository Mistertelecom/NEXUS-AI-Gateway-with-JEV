Dua cara untuk menempatkan Cursor di belakang OmniRoute tanpa sesi IDE:

1. **Penyedia `cursor-api`** (kartu "Cursor API", alias `cua`): penyedia berbasis kunci API yang menyimpan kunci API pengguna Cursor (`crsr_…`, dibuat di
   `https://cursor.com/dashboard/api`). Klien OmniRoute mana pun kemudian dapat mengakses
   model Cursor melalui `/v1/chat/completions` sebagai `cursor-api/<model>` atau
   `cua/<model>`, dengan lapisan kuota, fallback, dan pencatatan yang biasa digunakan. Penyedia IDE
   (`cursor`, sesi OAuth/IDE) tidak berubah.
2. **Passthrough Cursor CLI**: arahkan Cursor CLI (`agent`) ke OmniRoute agar
   setiap RPC yang dibuat CLI diautentikasi dengan kunci API OmniRoute, diteruskan
   ke Cursor menggunakan kredensial koneksi `cursor-api`, dan dicatat di
   halaman Log.

## Mengapa kunci dipertukarkan

`api2.cursor.sh` menolak kunci mentah `crsr_…` sebagai token Bearer (401). Cursor
CLI terlebih dahulu mengirimkan kunci melalui POST ke `/auth/exchange_user_api_key` dan menerima JWT
sesi yang kedaluwarsa setelah satu jam; `refreshToken` yang dikembalikan memiliki
`exp` yang sama, sehingga penyegaran dilakukan dengan menukarkan ulang kunci tersebut.
`open-sse/services/cursorApiKeyAuth.ts` melakukan pertukaran tersebut, menyimpan satu token
sesi dalam cache untuk setiap kunci, menukarkannya kembali lima menit sebelum kedaluwarsa, dan menghapus
token dalam cache ketika Cursor memberikan respons 401. `CursorExecutor` memanggilnya tepat sebelum membuka
stream upstream untuk koneksi `cursor-api`.

## Penyedia `cursor-api`

Registri: `open-sse/config/providers/registry/cursor/index.ts`
(`cursor_apiProvider`, `authType: "apikey"`, dengan `format`, `baseUrl`, dan
`models` yang sama seperti `cursor`). Kartu katalog:
`src/shared/constants/providers/apikey/specialty-media.ts`. Peta executor:
`open-sse/executors/index.ts` (`"cursor-api"` / `cua` →
`new CursorExecutor("cursor-api")`).

Dasbor: Penyedia → Cursor API → Tambahkan kunci API.

REST:

```bash
curl -sS -X POST http://localhost:20128/api/providers \
  -H "Content-Type: application/json" \
  -d '{"provider":"cursor-api","name":"cursor-api-key","apiKey":"crsr_…","priority":1}'
```

Kemudian:

```bash
curl -sS http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <omniroute-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"cursor-api/auto","messages":[{"role":"user","content":"say PONG"}]}'
```

Catatan:

- Daftar model untuk `cursor-api` berasal dari registri statis Cursor (daftar
  yang sama dengan yang digunakan sebagai fallback oleh penyedia IDE); instalasi `cursor-agent` tidak
  diperlukan pada host OmniRoute.
- `POST /api/providers/{id}/refresh-cursor` hanya digunakan untuk penyedia IDE `cursor`;
  koneksi `cursor-api` tidak memiliki sesi IDE untuk diperbarui.

## Passthrough Cursor CLI

Rute: `src/app/api/cursor-cli/[...path]/route.ts` →
`open-sse/handlers/cursorCliProxy.ts`. Prefiks `/api/cursor-cli/`
didaftarkan dalam `src/shared/constants/publicApiRoutes.ts` karena handler
menerapkan autentikasinya sendiri:

| Path                                                                                                                            | Autentikasi yang diharapkan dari CLI | Tindakan OmniRoute                                                                                                                                                                                 |
| ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /auth/exchange_user_api_key`                                                                                              | `Bearer <OmniRoute API key>`         | Memvalidasi kunci, membuat JWT HS256 berdurasi 1 jam (ditandatangani dengan `JWT_SECRET`), lalu mengembalikannya                                                                                   |
| setiap path lainnya (`/aiserver.v1.*`, `/agent.v1.AgentService/RunSSE`, `/aiserver.v1.BidiService/BidiAppend`, `/v1/traces`, …) | `Bearer <that JWT>`                  | Memverifikasi penerbit/audiens/kedaluwarsa, memilih koneksi `cursor-api` yang aktif, mengganti header Authorization dengan token Cursor yang telah dipertukarkan, lalu menyalurkan kembali respons |

CLI mendekode `exp` dari token apa pun yang diterimanya, sehingga memberikan
token opak akan membuatnya melakukan pertukaran ulang sebelum hampir setiap permintaan; JWT yang dibuat
mencegah hal tersebut. Respons 401 dari OmniRoute membuat CLI melakukan pertukaran kembali.

### Penyiapan

1. Buat kunci API OmniRoute (Dasbor → Kunci API) dan koneksi `cursor-api`.
2. Instruksikan CLI untuk menggunakan HTTP/1.1 bagi stream agen. Di
   `~/.cursor/cli-config.json`:

   ```json
   { "network": { "useHttp1ForAgent": true } }
   ```

   Tanpa ini, CLI membuka giliran agen melalui HTTP/2 ke host agen yang
   dikonfigurasi secara terpisah dan hanya RPC control-plane yang melewati
   endpoint tersebut.

3. Jalankan CLI terhadap OmniRoute:

   ```bash
   export CURSOR_API_ENDPOINT=http://localhost:20128/api/cursor-cli
   export CURSOR_API_KEY=<omniroute-api-key>
   agent -p --trust "Reply with exactly OK"
   ```

Setiap hop masuk ke Log sebagai penyedia `cursor-api`, dengan jenis permintaan `cursor-cli`,
path `/api/cursor-cli/<rpc>`, yang dikaitkan dengan kunci API OmniRoute dan
koneksi yang melayaninya.

### Mode kegagalan

| Situasi                                                  | Respons terhadap CLI                              |
| -------------------------------------------------------- | ------------------------------------------------- |
| Kunci OmniRoute tidak dikenal dan `REQUIRE_API_KEY=true` | 401 `unauthenticated` saat pertukaran             |
| `REQUIRE_API_KEY=false`                                  | sesi anonim (mencerminkan perilaku `/v1/*`)       |
| JWT sesi kedaluwarsa / asing / telah dimanipulasi        | 401, CLI melakukan pertukaran ulang               |
| Kunci API OmniRoute dicabut setelah pertukaran           | 401 pada RPC berikutnya                           |
| Tidak ada koneksi `cursor-api` yang aktif                | 503 `unavailable`                                 |
| Cursor menolak kunci koneksi                             | 401 `unauthenticated`, sesi yang di-cache dihapus |
| Upstream tidak dapat dijangkau                           | 502 `unavailable` (pesan disanitasi)              |
| `JWT_SECRET` belum disetel                               | 503 saat pertukaran                               |
