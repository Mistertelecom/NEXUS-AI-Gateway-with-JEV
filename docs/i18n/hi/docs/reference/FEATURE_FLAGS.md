> रनटाइम टॉगल, जो OmniRoute के व्यवहार को **बिना दोबारा डिप्लॉय किए** बदलते हैं।
> यहाँ सूचीबद्ध प्रत्येक फ़्लैग को
> [`src/shared/constants/featureFlagDefinitions.ts`](../../src/shared/constants/featureFlagDefinitions.ts)
> में परिभाषित किया गया है — यही सत्य का एकमात्र स्रोत है। डैशबोर्ड और REST API दोनों
> उस फ़ाइल से पढ़ते हैं, इसलिए नीचे दी गई तालिका उससे 1:1 मेल खाने के लिए जनरेट की गई है।

## फ़ीचर फ़्लैग क्या हैं

फ़ीचर फ़्लैग एक नामित टॉगल (बूलियन या एनम) है, जिसका मान रनटाइम पर बदला जा सकता है
और डेटाबेस में सहेजा जा सकता है, जिसके लिए प्रोसेस को दोबारा डिप्लॉय करने की आवश्यकता नहीं होती। प्रत्येक
फ़्लैग को एक `FeatureFlagDefinition` द्वारा वर्णित किया जाता है, जिसमें `key`, `label`,
`description`, `category`, `defaultValue`, `type`, और `requiresRestart` संकेत होता है।

### निर्धारण क्रम

किसी फ़्लैग का **प्रभावी मान**
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) द्वारा निम्नलिखित
वरीयता क्रम के अनुसार निर्धारित किया जाता है (सर्वोच्च वरीयता प्रभावी होती है):

1. **DB ओवरराइड** — `feature_flags` नेमस्पेस के अंतर्गत `key_value` तालिका में
   संग्रहीत मान (डैशबोर्ड या REST API के माध्यम से सेट किया गया)।
2. **एनवायरनमेंट वेरिएबल** — `process.env[<KEY>]`, यदि सेट किया गया हो और रिक्त न हो।
3. **परिभाषा का डिफ़ॉल्ट** — `featureFlagDefinitions.ts` से प्राप्त `defaultValue`।

किसी बूलियन फ़्लैग को **सक्षम** माना जाता है, जब उसका प्रभावी मान `"true"`,
`"1"`, या `"yes"` हो (`isFeatureFlagEnabled()` देखें)।

> [!NOTE]
> अधिकांश फ़्लैग के लिए **समान नाम** वाला एक संबंधित एनवायरनमेंट वेरिएबल भी होता है,
> जिसका दस्तावेज़ीकरण [`ENVIRONMENT.md`](./ENVIRONMENT.md) में किया गया है। फ़्लैग का DB ओवरराइड
> उस एनवायरनमेंट वेरिएबल पर वरीयता लेता है। `requiresRestart: true` वाला फ़्लैग
> तुरंत सहेजा जाता है, लेकिन उसे केवल प्रोसेस शुरू होने पर दोबारा पढ़ा जाता है — उसे टॉगल करने पर
> डैशबोर्ड में **"सर्वर पुनः आरंभ करें"** बैनर दिखाई देता है।

जिसका उपयोग तब किया जाता है, जब न तो कोई DB ओवरराइड और न ही कोई एनवायरनमेंट वेरिएबल मौजूद हो।

## फ़्लैग टॉगल करना

### डैशबोर्ड

**Dashboard → Settings → Feature Flags**
(`/dashboard/settings/feature-flags`) पर जाएँ। ग्रिड
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
में ये सुविधाएँ उपलब्ध हैं:

- कुंजी या विवरण के आधार पर **खोज**, और श्रेणी के आधार पर **फ़िल्टर** (साथ ही एक कृत्रिम
  **Requires Restart** दृश्य)।
- बूलियन फ़्लैग के लिए एक **टॉगल** और enum फ़्लैग के लिए एक **ड्रॉपडाउन**
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`)।
- प्रत्येक फ़्लैग के लिए एक **स्रोत बैज** — `DB`, `ENV`, या `DEF` — जो दिखाता है कि
  प्रभावी मान कहाँ से आया है।
- ओवरराइड हटाने के लिए एक **रीसेट** बटन (केवल `DB`-स्रोत वाले फ़्लैग के लिए दिखाया जाता है),
  और सबसे नीचे एक **सभी ओवरराइड रीसेट करें** बटन।
- किसी `requiresRestart` फ़्लैग को बदलने पर एक **सर्वर पुनः आरंभ करें** बैनर।

### REST API

सभी ऑपरेशन एक ही रूट से होकर जाते हैं:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts)।
प्रत्येक मेथड के लिए प्रमाणीकृत डैशबोर्ड सत्र आवश्यक है (अन्यथा `401`)।

#### `GET /api/settings/feature-flags`

प्रत्येक फ़्लैग को उसके प्रभावी मान, स्रोत और सारांश के साथ लौटाता है।

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... सभी 72 फ़्लैग
  ],
  "summary": {
    "total": 56,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

किसी एक ओवरराइड को सेट करें या हटाएँ। बॉडी: `{ key: string; value?: string }`।
`value` को छोड़ देने पर ओवरराइड हट जाता है (env / डिफ़ॉल्ट पुनर्स्थापित होता है)।

```bash
# DB ओवरराइड सेट करें
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# ओवरराइड हटाएँ ("value" के बिना)
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

प्रतिक्रिया नए `effectiveValue`/`source`, `previousValue`/
`previousSource`, और `requiresRestart` को लौटाती है। अज्ञात कुंजियाँ और अनुमत सीमा से बाहर के enum
मान `400` के साथ अस्वीकार कर दिए जाते हैं।

#### `DELETE /api/settings/feature-flags`

सभी DB ओवरराइड एक साथ साफ़ करता है, जिससे प्रत्येक फ़्लैग अपने env / डिफ़ॉल्ट
मान पर पुनर्स्थापित हो जाता है। `{ cleared: <count>, message: "..." }` लौटाता है।

> [!NOTE]
> `requiresRestart: true` वाले फ़्लैग केवल प्रोसेस रीलोड होने के बाद प्रभावी होते हैं।
> डैशबोर्ड का रीस्टार्ट फ़्लो `POST /api/restart` को कॉल करता है और फिर सर्वर के पुनः चालू होने तक
> `GET /api/health/ping` को पोल करता है।

## आपातकालीन बजट फ़ॉलबैक

`OMNIROUTE_EMERGENCY_FALLBACK` (श्रेणी `runtime`, डिफ़ॉल्ट `true`)
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts)
में आपातकालीन मुफ़्त-फ़ॉलबैक पथ को नियंत्रित करता है।
सक्षम होने पर, अपना बजट समाप्त कर चुके अनुरोधों को सीधे विफल करने के बजाय किसी मुफ़्त फ़ॉलबैक
प्रदाता/मॉडल पर रूट किया जाता है। इस व्यवहार को अक्षम करने और बजट समाप्त कर चुके अनुरोधों को
विफल होने देने के लिए इसे `false` (या `0`) पर सेट करें — डैशबोर्ड टॉगल, DB ओवरराइड, या
`OMNIROUTE_EMERGENCY_FALLBACK` पर्यावरण चर के माध्यम से।
(PRs #3741 / #3752 में डैशबोर्ड टॉगल के रूप में प्रदर्शित।)

## यह भी देखें

- [पर्यावरण वेरिएबल संदर्भ](./ENVIRONMENT.md) — अधिकांश फ़्लैग के लिए समान नाम वाला
  पर्यावरण वेरिएबल वहाँ प्रलेखित है (DB ओवरराइड को

- [`src/shared/constants/featureFlagDefinitions.ts`](../../src/shared/constants/featureFlagDefinitions.ts)
  — प्रत्येक फ़्लैग के लिए प्रामाणिक स्रोत।
- [`src/shared/utils/featureFlags.ts`](../../src/shared/utils/featureFlags.ts)
  — समाधान लॉजिक (`resolveFeatureFlag`, `isFeatureFlagEnabled`,
  `resolveAllFeatureFlags`)।
- [`src/lib/db/featureFlags.ts`](../../src/lib/db/featureFlags.ts) — `key_value` तालिका के
  `feature_flags` नेमस्पेस में DB ओवरराइड का स्थायी भंडारण।
